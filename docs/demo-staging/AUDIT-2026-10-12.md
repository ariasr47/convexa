# Demo / staging-on-mocks audit — 2026-10-12

Scope: the whole repo at `main` `8773ffa1` (PR #76 merged), audited for one goal: a staging build where every
feature runs on mock adapters, providers and seeded data, so Convexa stays fully demoable without Massive, a
broker or a paid LLM. Read-only audit (4 parallel code readers) plus a hands-on walk of the demo build
(`npm run build:dashboard:demo`, exit 0, served on :4217). Claims cite `file:line`; "inferred" marks reasoning not
run end to end.

## Answer

There are two mock layers today and neither is complete.

1. **Browser demo (PR #76)** — `libs/api/src/lib/demo/transport.ts` (1,450 lines) answers the API inside the
   browser; no backend runs. About 70% of the app clicks through. It is the cheapest public face ($0 on Pages).
   Its weaknesses are the **data** (each symbol is 4 numbers: `catalog/spy.seed.json` = base/step/phase) and the
   **headline flow** (the AI read is hard-coded `decision: 'no_trade'`, `transport.ts:509`).
2. **Backend facades** — the seams exist (`MarketDataPort::{Live,Fixture}` `market_data/mod.rs:122`,
   `FixtureCatalog`, `StockStreamHub::fixture` `ws.rs:83`, `PositionsProvider` + `StubProvider`, memory stores,
   `AI_REC_LOCAL_ONLY`), but only the broker is env-selectable. Fixtures are reachable only from capacity-harness
   constructors (`state.rs:801`, `capacity/harness_app.rs:89`); production refuses them (`state.rs:787-797`), and
   `MARKET_DATA_MODE=paused` answers 503 before the fixture arm (`analytics.rs:33` vs `:226`).

Production today: `convexa.pages.dev/demo-mode.json` → `"mode":"live"`; `/api/health` → paused API on Railway. A
visitor to the main URL gets 503s on every market read.

## Recommendation: one synthetic scenario, two consumers

Do not hand-author two mocks that drift. Build **one deterministic synthetic market** (option chains with an IV
smile and OI shape, daily + minute bars, trades, for the 6 demo symbols) in the backend's `FixtureCatalog`
format, then:

- **(a) Backend `MARKET_DATA_MODE=fixture`** serves it through the real Rust quant engine — full-stack staging,
  locally via a `docker compose --profile demo` that needs no `.env`.
- **(b) Export** the engine's computed bundles (ticker, scan, history, candidates, local-strategy rec) as the
  browser demo's seed snapshot.

Realism problems (identical scores, put wall off the strike grid, option marks that ignore IV and price, RSI 91)
disappear because real math produces the numbers. Synthetic data also avoids redistributing Massive-derived
chains (`libs/quant-engine/tests/fixtures/gex_SPY.json` `_note`).

Hosting: keep staging **static on Pages** (public, $0) plus **full stack local**. A Railway staging service adds
monthly cost for a dormant project.

## Decisions for the owner

1. **Position recommendations** have no UI in either mode. Build one (L) or drop them from the pitch.
2. **Research/capture subsystem** (~32k LOC: session archive, day tape, flat files, snapshots, research routes) and
   **two capacity harnesses** (~8.4k LOC): keep compiled, move behind a cargo feature, or archive.
3. **Railway production** serves a paused API that the demo never calls. Keep paying, or stop it once the static
   demo is the public face.
4. **Backend fixture mode** inverts deliberate production guards (B1). Acceptable only if refused under
   `APP_ENV=prod` with a test.
5. **Local recorded data** — `data/chain_snapshots` (192 MB) and `data/session_chain_archive_bodies` (100 MB) are
   gitignored, Massive-derived, and this machine has no backup. Decide whether to keep a private copy.
