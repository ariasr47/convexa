### FLAKY or timing-based
1. **Shared vendor counter, two different locks.** `COVERAGE_VENDOR_CALLS` is one process-wide counter, and `derive()` refuses to run when it is not 0 (`matrix.rs:287`).
   - `matrix.rs:1260-1273` sets it to 1 under matrix's own `TEST_LOCK` (`:655`).
   - `ensure_worker.rs:451-508` sets it to 1 under a different `TEST_LOCK` (`:204`).
   - The route tests reset it to 0 with no lock at all (`routes/research_session_coverage.rs:362-364`, then assert 0 at `:612`). Matrix's `begin_test` (`:728-733`) also resets it to 0.
   - When these run in parallel, a derive-based test can fail spuriously, or a poison test can be un-poisoned mid-run.
   - Fix: one shared `pub(crate)` test lock for the coverage module, or inject the counter.
2. **Fixed sleeps in `path_a.rs`.** Each test sleeps 50 ms "to let recv subscribe" (`:405, 435, 470, 508, 535, 561, 653, 690, 727`; 80 ms at `:588`).
   - If the receiver task subscribes later than that under load, events are lost and `drain_until` times out after 2 s.
   - `persist_fail_always_skip_line_no_occupant_desk_ok` asserts the skip log after a fixed 150 ms (`:735`).
   - `writer_channel_full_at_4096_yields_one_coalesced_gap_sse_still_flows` depends on a 150 ms sleep (`:597`) plus yield ordering, which its own comment admits.
   - Fix: subscribe inside `spawn_with` before `tokio::spawn` and pass the receiver in, then poll the skip log with a deadline instead of a fixed sleep.
3. **Shared warning latch.** `matrix.rs` `begin_test` clears the global warned set (`:657-659`) while `ensure_worker` tests emit latched warnings under a different lock. Distinct dates (2026-08-17 and -24) make this low risk.
4. **Brittle source match.** `ensure_worker.rs:511` matches a multi-line source string exactly, so a rustfmt change will break it. It is still floor; it is the only guard that coverage runs when ensure is off. Prefer a behavioural test of the `spawn` branch.
