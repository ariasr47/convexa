2. Product direction

Who it is for

You first — a solo operator/swing trader who lives in dark terminals, distrusts overclaiming UIs, and wants dealer positioning context that is honest when degraded. Secondary: a future founding cohort only after your ledger says the process helps.

Job to be done

Given dealer gamma structure on liquid names: where is price attracted or repelled, is the regime mean-reverting or trending, is there an actionable setup now, and what did I decide last time?

Positioning (honest wedge)

Own the wedge

Live single-ticker read (price / flow / flip) + interpretation (setups, score, AI that explains) + decision ledger. Few rivals couple all three with engineering honesty.

Refuse the war

0DTE per-second GEX, 3,500-ticker breadth, real order routing, free-broker AI toys. Different product, different bill, different ethics.

Brand system

“The Curvature Terminal” — numerals as personality; degraded/sim states styled as truth, not footnotes. Design canon SET 2026-08-10.

Monetization posture

Gated on ledger evidence + written data licensing. AI framed as explains, never “tells you what to trade.”

Non-goals (binding)

  • no-real-order-path — read positions OK; no live execution.
  • No silent score drift — score-change-is-deliberate-and-measured.
  • No second design system; tokens only via theme / tokens.ts.

5. Calculations (what the machine believes)

Two gamma sources (do not unify casually)

  • Vendor gamma → strike profile, walls, net/call/put GEX at current spot.
  • Analytic BS gamma → gamma flip on a spot ±20% grid (vendor has no grid).

They can disagree by design (e.g. wall at 450 vs flip at 420).

Core identities (standing)

  • Dollar GEX ≈ gamma · OI · 100 · S² · 0.01 (calls +, puts −).
  • Walls = max/min net-GEX strikes; flip = nearest zero-crossing of net GEX on the analytic grid.
  • DEX, vol/OI, IV skew, term structure are additive context — not score inputs under additive canon.
  • Opportunity score / tier / fingerprint: entry gate for AI and UI triage — must stay byte-identical under additive features.

Known maturity gaps in the math product

Raw vs vol-normalized GEX

External evidence (and roadmap X2): raw GEX often fails as a predictor; vol-normalized is the defensible form. Methodology note is part of shipping X2.

Score constants

Hand-tuned bands (e.g. gate 50, tier cuts) never outcome-validated for years of enrichment features. Ledger + score-lab exist to end that freeze-by-accident.

Intraday staleness

Market’s #1 churn complaint for peers: “day-old levels.” Your live flip/flow path is a relative strength; chain refresh cadence is still a product constraint.

Hist options replay

Full PIT chain backtest is hard/expensive (plan-gated). Current path: capture live features + Massive daily labels — correct interim architecture.

Design principles that actually constrain code

  • Best-effort isolation: optional computations fail → null field, not 5xx on the trader path.
  • Live vs static isolation: SSE drop dims live tiles; last bundle keeps rendering.
  • Operator path separation: /_ops/metrics off trader chrome.
  • Structural enforcement: prefer build-breaking guards over prose (module boundaries, scans, pins).
  • Interface contract: FE↔BE single source; conformance receipts at ship.

Research subsystem (new maturity)

Slow-lane → scan_structure_history (score, drivers, walls, GEX, IV/HV) → join-outcomes (Massive daily) → score-lab. This is how quant grade climbs from 3 → 4 → 5.

7. Security

Standing posture

No real order path; secrets encrypted at rest (BYO AI / broker tokens); server-side gates for state-bearing actions; metrics token on prod; public rate limit; registration fail-closed.

Broker surface

First real-account connection already triggered system-6-style review. Read-only only. Credential storage is the sensitive core — keep attack surface minimal.

AI surface

AI is advisory; gated; BYO key preferred; shared key limited to admin allowance. Never score input.

Open residual risks

Process-local AI meters on multi-replica; browser-local durable stores for some FE history; data licensing landmine before any paying user (Massive personal-use vs redistribution).

Before L4 (billing / strangers): written vendor licensing, ToS/disclaimers, abuse economics, and a security pass on multi-tenant assumptions — not more GEX tiles.

  • GEX cache + warm set; rate limits on public vendor-cost routes.
  • FE route-level code splitting (major chunk work already done).

Users churn on stale structure more than on bundle milliseconds. Optimize perceived freshness (honest stale flags, live flip, warm paths) before micro-optimizing chart paints.

10. Best recommendations (ranked)

Ordered for a 10–25 h/wk owner with edge-first frame. Each is actionable.

1
Protect the evidence clocks

Keep prod capturing structure history (done). Mirror every real trade in the app (N2). Re-run join + score-lab weekly until large_abs_move lift is stable across weeks — not days.

2
Ship X2 — vol-normalized GEX + methodology note

Highest roadmap leverage on signal quality while score-lab matures. Addresses external “raw GEX doesn’t work” evidence and competitor staleness narrative.

3
Do not reweight live score from the thin 1d lab

Treat structure_event strength as a research lead. Any score change needs score-change-is-deliberate-and-measured + multi-week before/after.

4
Decide distribution consciously

Either start the deferred X habit after personal quirks settle, or formally stay “private instrument” for 90 days — but don’t pretend growth will appear from features alone.

5
Stand up a test environment before heavy hist research

Separate Postgres + APP_ENV=test. Avoid laptop full-admin against prod for join jobs; export samples via history API is fine interim.

6
Alerts (X3) after X2, not before

Alerts amplify whatever signal you have. Amplifying an unmeasured score burns trust.

7
Commercial path only after licenses + N

Databento/OPRA evaluation (L2) and billing (L4) after edge test and written redistribution rights. Personal-use Massive is fine for solo; it is not a multi-tenant business foundation.

90-day focus (suggested)

  1. Weekly score-lab ritual (SPY/QQQ + maybe IWM) — log lift in a short note.
  2. Design + ship vol-normalized GEX with public methodology page in-app or docs.
  3. Ledger N from real mirrored trades — even small N beats none.
  4. Optional: one distribution experiment or explicit private-only season.
