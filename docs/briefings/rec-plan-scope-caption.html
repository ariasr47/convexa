One quiet sentence that stops a wrong trade.

We are not shipping a new signal, a smarter model, or a checked plan. We are shipping a scope boundary: when Convexa shows a trade plan, it will say out loud which fields nobody checked.

The hole this closes

Same failure class as the last two AI-grounding ships: a trader treats an unchecked field as verified and sizes or enters on it.

Convexa can already check three risk/exit numbers against its own computed levels: stop, target, and invalidation. Those can carry a small “traces to / near / inside” clause.

Six other fields sit on the same card as ordinary stated values:

Structure Strike(s) Expiration Entry trigger Time horizon Confidence

They have no clause. After the last two ships, a reader who learned “a clause means Convexa checked it” can invert the lesson: no clause means it was checked too, or it wouldn’t be sitting there so cleanly.

A trader sees a checked target next to an unchecked strike, treats the whole plan as verified, and enters. That is a wrong trade.

We do not start checking those six fields. We name the boundary so “no clause” cannot be read as “checked.”

The three-ship arc

This is half two of a hole the last ship was not allowed to call closed.

Ship 1

Numbers the model asserts

If the AI writes “stop 412,” Convexa must either trace that figure to a computed field or say it could not. Measured at ship: 44% of asserted numbers did not trace — and used to render as fact.

Ship 2

Numbers the model omits

A missing strike used to print the reserved no-entry dash. “We never got a strike” looked identical to “no strike applies.” Closed vocabulary: not given / unavailable / unrecognized — never the no-entry mark.

This ship

The inference that remains

Half two of the same item: even with honest absence marks, a reader can still generalize “no clause means checked” onto the six plan fields. One section caption is the remaining mechanism. Until this ships, that item may not be recorded closed.

What a hurried trader can conclude

Two green clauses sit next to a clean strike and a clean trigger. Nothing on the plan row says those fields were never run through Convexa’s numbers. The card looks internally consistent. That consistency is the defect.

Checked: invalidation, target.
Unchecked, looking checked: structure, strike, trigger, confidence.

The exact sentence

Closed constant. Never interpolated. Never “because strikes were empty.”

Structure, Strike(s), Expiration, Entry trigger, Time horizon and Confidence aren't checked — only the stop, target and invalidation level are.

ClauseWhy it is there
Names all six plan labelsUses the same words already on the row. No new vocabulary.
“aren't checked”Permanent scope: none of the six enters the figure-grounding set. Not a per-rec diagnosis.
“only the stop, target and invalidation level are”Names the allowlist, not “the numbers below” — layout can drift.
No verified / confirmed / safe / trustedThose words are banned as claims about the plan. Traceable is not the same as correct.

Chrome: quiet secondary caption, block display, no warning icon, no amber alarm, no new animation. Same honesty pattern as the reasoning-prose caption already in the analysis drawer.

When it appears — a two-question machine

Show/hide is structural. It does not inspect whether a field looks “stated” or whether a risk clause rendered. A boundary that vanishes when every field is an absence mark would teach “no caption means full coverage.”

Never used as a gate

  • Who paid for the key (key_source)
  • Whether strikes are empty
  • Whether a stop/target clause rendered
  • Whether the trader opened analysis

Local-rules envelopes can carry a real admin key and still always state a structure. Gating on “keyless” would either hide the model path or hang a permanent banner on the rules path.

Odd case we accepted

If the card token is not_applicable (local-only body with nothing checkable) and a trade plan row still mounts, the caption shows. Hide is only the word local_rules. A second hide token would need a server change, which this feature forbids.

Where it sits

On the pinned Decision card — the surface a trader can act from without opening the drawer. One instance. Never inside the wrapping plan-field row (that row is a horizontal flex; a block caption inside it becomes a seventh chip).

  1. Trade · bias
  2. Six plan fields (the row)
  3. ← caption lands here, as the next sibling
  4. Thesis lead, if any
  5. Risk grid (max risk / invalidation+clause / entry / target+clause)

Analysis may repeat plan labels. It must not grow a second copy of this caption. The drawer already has its own prose caption: numbers written in the reasoning aren’t checked.

What we are not shipping

Not a smarter check

Plan fields do not enter the grounded set. The model is not asked to ground them. Stop / target / invalidation stay the only allowlist.

Not per-field chips

No tint, tooltip, or “not checked” mark on Structure or Strike. That would invent a new type register and re-open line budget.

Not a server change

Empty API diff. Score, tier, and fingerprint stay byte-identical. No new wire field.

Not a banner on local rules

The rules path always emits a trade shape when a setup exists. A permanent caption there would go numb and lose its meaning.

Not Accept / prefill work

The simulated entry dialog is untouched. Absence marks on the six fields stay as shipped.

Not a measurement

We are not yet measuring whether readers actually drop the inference. That is future work, named as such.

Known leftovers — shipping as written

The design review found these. They did not block the spec. They will still be true after ship.

The second clause can disagree with the card line

The caption says stop / target / invalidation are checked. On a missing-grounding or not-applicable envelope, a sibling line on the same card can say this read wasn’t checked at all. Distinct, and in that state opposite. The first clause (“plan fields aren’t checked”) remains true.

Grid Entry still has no local mark

The risk grid restates the entry trigger beside a checked target, with no clause on Entry. The caption sits above the thesis, not in that cell. We forbade putting it in the grid. The adjacency remains.

If we ship

Shipping archives this feature and updates the standing notes. It is the first time we are allowed to record the leftover “no clause means checked” hole as closed.

It does not make plan fields true. It does not make the model better. It makes the card stop implying a check that never ran.
