The trap

0.932 wasn't skill. It was a circle.

Up to half of your score's points come from how close price is to the call wall, the put wall, and the gamma flip. And structure_event means: price reached a wall, or crossed the flip.

So the score was being congratulated for predicting the thing it is largely built out of. That isn't a forecast — it's a definition wearing a forecast's clothes. Before, a reader had to notice this. Now the tool says it, on the cell, every run.

The mark isn't a guess or a hand-kept list. Every candidate and every outcome must declare what it is built from, and the tool intersects those declarations. Leave a declaration out and the build fails — it cannot quietly un-mark a cell. A default run over three symbols produces 60 cells: this grid once pooled, then once per symbol.

The part that took three tries

Every blank tells you which kind of blank it is

"No number here" has at least four different meanings, and confusing them is how research files start lying. A cell with too few samples is not the same as a cell that cannot have a number at all. So each state gets its own words — and none of them is a bare dash.

What a cell says when it can't give a clean answer

hatched = no number can exist
0.61 · thin (n=12, floor 30) Below the sample floor. The value still shows, with its warning attached — hiding it would turn "shaky" into "impossible," which is a different lie.
undefined on this data There is no outcome to score against, so no accuracy figure can exist. It names the missing precondition instead of printing a placeholder.
not evaluable here The combination doesn't apply at this scope. Not an error, not an empty result — simply outside what this cell can be asked.
not symbol-comparable (see the per-symbol cells) Gamma magnitude scales with each symbol's own float. Pooling them makes a number that looks fine and means nothing, so the cell says so in its place.

The failure this prevents is concrete. The first build wrote a 50/50 accuracy score onto rows that had nothing to be accurate about — in the one file meant to be the permanent record of a week's research. It read perfectly fine in the source code. Only opening the file the tool actually produced caught it.

What it deliberately cannot do

The lab measures. It never edits.

A measuring tool that can quietly move the thing it measures is worthless. So the lab has no route to your score at all — not a weight, not a threshold, not the entry gate.

The lab · reads only

Loads your saved diary, pairs each snapshot with what price did next, ranks five candidates against three outcomes, writes a report and a data file.

no path

Your score · untouched

Weights, constants, the entry gate and the fingerprint are byte-for-byte what they were. No lab result can authorize a change to them on its own.

Changing the score stays a separate, deliberate decision that has to state its reasoning and record a before-and-after on real tickers. This tool is the prerequisite for that — you can't improve a score you can't measure.

How it got here

The two worst bugs were invisible in the code

Every build was checked by a separate reviewer that fixes nothing and only reports. It sent the work back twice. Both times the defect was something reading the source would never reveal.

Build and check, alternating

the checker never fixes · the builder never grades
Build 1 Froze two snapshots of the diary before they aged out. The buffer holds about 3½ days at the current rate, and the rows this whole investigation rests on were next to go.
Build 2 The comparison engine, the report, the safeguards — 18 tasks.
Check 1 sent back The report file invented statistics. Rows with nothing to score carried a chance-level accuracy number anyway. The source looked correct; the file it produced did not.
Build 3 Fixed 19 of 21 findings, including that one.
Check 2 sent back A safeguard had the right name and the wrong reach. The test guarding against a hardcoded figure inspected one file — not the file where that text is actually written. It would have stayed green through the exact mistake it existed to catch.
Build 4 Both remaining gaps closed, each with the test coverage that was missing.
Check 3 passed All 78 criteria re-checked, not only the repaired ones. The checker deliberately broke each new safeguard to confirm it fails when it should, then put the code back exactly as it was.

What isn't finished

  • The newer snapshot has no outcomes yet. Producing them needs a data-vendor key this machine doesn't have, so the strongest test of the gamma candidates hasn't run. The affected checks skip loudly rather than passing quietly — and nothing was invented to fill the gap.
  • Asking for the same symbol twice prints it twice. Every number stays correct; it's cosmetic, and it predates this work. One line to fix.
  • A stray leftover process keeps rewriting a data file and can't be killed on this machine. It cost two review passes real time, so it's written down before it costs a third.
the point

Your score has never been validated against an actual outcome, and until now there was no instrument honest enough to try. Now there is — including the part that tells you when a good-looking result is really a mirror.
