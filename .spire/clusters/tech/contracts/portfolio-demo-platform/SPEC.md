# portfolio-demo-platform — spec

**Source brief:** `.spire/clusters/tech/contracts/portfolio-demo-platform/BRIEF.md`
**Council:** R1 positions · R2 critiques · `council/decisions.md`
**Status:** APPROVED 2026-10-07 (owner-delegated implementation authority; S2 PASS)

## 1. Goal + scope

Give a visitor a populated, explicitly synthetic tour of the existing Convexa product without an account, paid feed, AI key or broker connection. Give Rodrigo a source-linked visual atlas that explains which behavior the static demo shows and which behavior belongs to the unchanged live Rust service. The build-time mode choice is reversible: existing installations default to live, while the portfolio build explicitly selects demo.

**In scope:**

- An accessible, interactive backend atlas under `docs/backend-atlas/`: current and proposed architecture diagrams, stack and module map, screen/widget-to-source map, API/store boundaries, request and job traces, visitor journeys, mode and environment runbook, measured build/test/deploy evidence, and limitations. The existing `design-canvas.html` is the pre-build design artifact.
- A static, browser-local demo of the actual landing, scanner/screener, ticker overview, simulated portfolio/orders/track record, alerts, settings/personas, command search, authored sample analysis, and read-only sample broker holdings. An intentionally inert coming-soon affordance stays inert; an unavailable datum is labeled at its widget.
- Ticker-local Technical analysis and Research views, one authored case for each supported symbol, a local sample stream, editable demo book and preferences, explicit reset, and static Pages deployment after build and hosted checks.
- Production-build cache correctness, route-size and duration measurements against the recorded live baseline, and economical regression evidence.

**Out of scope:** Rust/API changes, a Rust scenario compiler/exporter, new live bars or research endpoints, backend demo profile, paid-data restoration, real signup/OAuth/key collection, provider AI calls, real broker orders, external news/citations, operator archive access from trader UI, strategy or score changes, production data/schema migrations, Railway deployment, and an installable offline/PWA system.

**Future (deliberately deferred):** vendor-backed live public bars/research, a hosted backend demo that proves Rust runtime behavior, and real broker integration require separate decisions, funding/data rights and authorization.

## 2. Architecture

**Composition and ownership.** `VITE_DATA_MODE=demo|live` is validated at production build/composition. Unset means `live` for compatibility; any other explicit value fails the build. Vite embeds the selection, so switching requires rebuild and redeploy. A mode-specific provider factory is chosen before React mounts. `libs/api/src/lib/client.ts` remains the typed ordinary-HTTP seam: its demo fetch implementation dispatches the complete current method/path inventory to local, `Response`-compatible handlers; unknown paths or methods fail closed with a typed `demo_unavailable` error and never call browser fetch. Existing `convexa.ts` and `broker.ts` exports, generated `paths`/DTOs and the live arm retain their signatures and behavior. The two public EventSource call sites (ticker in `convexa.ts`, scanner in `useLivePrices.ts`) use one typed subscription boundary with mode-specific arms, lifecycle teardown, bounded sample frames and explicit gap/pause handling. Demo frames may update local sample display/marks but have `live: false`; they never mint `LiveMassive`, session tape, genuine liveness, production archive occupancy or live motion. Browser network loss alone does not pause already loaded local playback.

The provider factory exposes finite domain capabilities for scenario provenance, local bars and research, demo session/eligibility, browser book, and stream control; the exact exports and union shapes are in `INTERFACE_CONTRACT.md`. New bars/research methods are application-local provider methods. Their live arm returns `unavailable: live_provider_missing`; it never imports demo fixtures as a live response or reads `/_ops/research`. App shell gates route access by mode: demo `Demo visitor` reaches scanner/positions without signup, while live auth and Rust server gates remain authoritative. Demo credential and OAuth handlers refuse before navigation or request; operator metrics/research direct fetch and token paths are unavailable in public demo. Existing trader routes remain separate from operator routes. A structural no-egress guard and built-browser check cover HTTP, EventSource/WebSocket, OAuth navigation, direct operator fetch, broker refresh and exported actions, not merely first paint.

**One authored scenario.** A versioned, browser-bundled catalog supports exactly `SPY`, `QQQ`, `AAPL`, `MSFT`, `NVDA`, `TSLA`, with one authored anchor `2026-10-07T18:30:00Z` (14:30 Eastern during the market session), independent of wall clock and first visit. All visible synthetic dates, DTE, spot, chain, contract marks, scanner rows, structure history, 60 daily OHLCV bars ending at the anchor, portfolio/orders/decisions, alert examples, analysis and research refer to that scenario ID and anchor. The shared six-symbol registry is small; each symbol has one canonical small JSON seed asset containing `symbol`, `base`, `step` and `phase`. A lazy, same-host static-asset fetch loads and validates that seed before the existing `makeScenario` factory builds its authored catalog; it does not add domain math. Vite emits non-inlined asset URLs so a failed first load can issue a new request on Retry. Cache fulfilled scenarios and concurrent loads, remove rejected loads from the cache, and do not maintain independent TS seed copies. Symbol-specific chart/research modules remain route-lazy. Static catalog asset retrieval is ordinary same-host asset traffic, not an API, vendor or broker egress. Price playback is a bounded deterministic sequence and its offset is local simulation state, never a re-dating of authored vendor history. Broker sample holdings are read-only and distinct from the editable paper book. P/L, totals and marks derive from linked sample positions/contract marks; exports retain scenario ID, as-of and sample authorship. Curated fixture values are validated against their stated inputs; the catalog is not described as an output of the Rust quant helper or an observed historical session. **Public sample records are newly authored synthetic data:** never copy `POS_CAPTURE_*`, `POS_CB_*` or `BOOK_CAPTURED_COMPLETE` from `apps/dashboard/src/app/features/trading/broker/fixtures.ts` (captured owner Webull records), nor import `features/auth/testBackend.ts` into production because it imports Vitest. Generated DTOs and harmless test fixtures can guide shape only; stale dates and provenance are rebuilt. No second market analytics engine is built.

**Exact supported query projection.** Each symbol's three authored expiries are `2026-10-09`, `2026-10-16`, `2026-11-20` (DTE 2, 9, 44 at the anchor). The full-chain snapshot is the base. Ticker query supports omitted DTE, integer `minDte`/`maxDte` in `0..60` with `min <= max`, and omitted or any subset of those three expiry dates; DTE and explicit expiry filters intersect. The current UI's zero-selected-expiry state displays its existing “No expirations selected” explanation without requesting a false bundle. For each **nonempty effective expiry set** there is one of exactly seven curated, validated variant patches per symbol, keyed by the sorted date set; DTE bounds only select that set, never trigger a fresh market computation. A variant coherently materializes the expiry-sensitive strike profile, GEX/DEX, walls/flip/peak and window labels **together with** their dependent `signals.distances`, regime/note, setups, score/drivers, tier, prime eligibility, state fingerprint, `ai_eval` gate and any market-context/dealer-flow/candidate/sample-analysis claim based on those values. Full-chain max pain, put/call OI, Vol/OI, IV/HV/IV rank and term structure retain their explicitly full-chain basis across variants. Every required wire member must be coherently authored for each offered set; an optional dependent value lacking a defensible basis is null/unavailable at its consumer, never inherited from the all-expiry variant as a plausible fact. The catalog includes a SPY all-expiry versus November-only case whose wall/flip, distance, setup/score and fingerprint materially differ, so G2 can detect stale dependent fields. These are authored snapshot variants, not a runtime analytics engine or claimed Rust output. `darkPool=true` or omitted includes the authored, side-unknown off-exchange context; `false` is explicitly unsupported in demo because live semantics omit off-exchange **and its capped score contribution**, which this bounded catalog does not recompute. The current ticker UI fixes this control on. A `position` input is accepted so an open demo book does not break the ticker; the base bundle and contract marks still load, while `position_eval` remains `null` with a visible sample-position-evaluation unavailable state. Do not synthesize a position evaluation from `plPct`. Contract lookup supports only authored chain contracts and returns `null` for absent contracts. Unsupported symbol, expiry, out-of-range/noninteger DTE or other unsupported projection returns typed `demo_unsupported`/`demo_unavailable` at that control; no unrelated variant or live fallback. Scanner client filters/sort/URL state operate over the same six rows, saved view and palette universe. A valid filter may intentionally yield zero rows; it must not change the underlying scenario.

**Populated normal demonstration.** The ordinary loaded view for **each of the six symbols and each of its seven nonempty selected-expiry sets** has finite, visible IV skew, labeled full-chain term structure, dealer-flow projection, Market Context trend/shape/flow/ATR, full-chain IV rank, and selected-structure volume-normalized GEX using the existing `TickerBundle` DTO and widgets. It also has a quoted ATM straddle move for a selected expiry, at least three fresh-positioning strikes above the displayed Vol/OI cutoff, and at least three side-unknown off-exchange blocks with nonzero, internally consistent totals. `position_eval:null` is the narrow normal-view exception; intentionally unsupported queries, a real load failure, an invalid optional reading and deliberate degraded scenarios retain their truthful unavailable states. Full-chain indicators stay labeled full-chain even in a filtered view. Fixture arithmetic ties strikes, volume/OI, contract quotes, IV observations, profile, variant-dependent signals and derived display measures to the same authored inputs; it never imports Rust output or creates a second quant engine. The existing 60-bar indicator implementation supplies bars-derived trend/ATR, while finite authored IV history and variant patches supply the other context. The exact field and arithmetic obligations are in `INTERFACE_CONTRACT.md`.

**Sample tape standing.** A demo frame may carry authored net flow over its named window, bid/ask spread, selected-variant gamma flip, mid and scenario timestamp through the existing sample stream. An application-local `sample` presentation standing lets the current tape and structure mid read those numbers with `Sample tape`/scenario-time captions while `LiveUpdate.live` stays false, `session_tape` stays absent and every genuine-live predicate remains false. The standing is local to the dashboard store/presentation and cannot unlock `LiveMassive`, live pulse/dot/flash/trail or order execution; paper orders still use their separate `demo_simulation` standing. Pause and finite end retain last displayed figures and their sample timestamp, with the existing explicit pause/end copy. Live mode retains its current genuine-live standing and labels.

**Browser state before hydration.** The build's validated mode produces one classic, blocking first-paint script in `index.html` through Vite `transformIndexHtml`; it defines `window.__CONVEXA_BOOT__` with the mode and **one** key resolver before its first localStorage access. The script's existing dark/light paint read uses that resolver, so demo never falls through to `convexa.theme-paint`, `convexa.uiprefs.v1` or `gammaflow.uiprefs.v1`. `libs/api` and the app call the same bootstrap resolver, not a second mapping. `src/main.tsx` statically imports the storage-only `src/prebootstrap.ts`, which statically imports `initializeDemoWorkspace` from the public `@convexa/api` barrel without importing App/store modules. The entry calls that initializer before dynamically importing `src/mountApp.tsx`, whose imports contain App/stores, then renders. This ordering prevents import-time store access before seeding while keeping the API library a static Nx consumer. Demo keys use `convexa.demo.v1.*`; live keys and `gammaflow.*` legacy reads stay exclusively in live mode. The resolver scopes every current and legacy localStorage read/write, migration reader, outcome/export source, position touch time, orders, alerts, personas, recent tickers, scanner saved view, settings/UI preferences, first-paint theme key and local book sync. A demo seed/version sentinel is written only after the absent demo namespace is initialized. A present empty/deleted record is a user edit and is never re-seeded on reload; malformed or unreadable bytes are preserved and their store's write-fault latch refuses overwrite. Reset Demo enumerates only demo-owned keys, then **reloads** to rehydrate every singleton/store from the fresh seed; it cannot clear a live or legacy key. Demo session and GET/PUT book operate locally and cannot synchronize with the live server.

**Paper order and clock seam.** One module-scoped demo controller starts at `2026-10-07T18:30:00Z`, advances a finite authored frame sequence by five scenario seconds per wall second to a hard end at `2026-10-07T19:00:00Z`, and emits each frame/status to all subscribers. It admits only one bounded asynchronous frame batch at a time. Pause, end and any observer-cohort change invalidate pending batch work; after each awaited catalog load, the controller rechecks the batch identity, playback state, offset and current observers before delivery. Thus a newly subscribed observer waits for a new frame, and no old frame reaches replacement subscribers, a paused controller or the finite end. Unsubscribing one page removes only that observer; the controller stops its timer when no observers remain, does not catch up from wall time, and resumes at its current offset on the next subscription. Reload restarts the offset at the authored anchor while retaining visitor book edits; terminal orders never replay, pending orders await a **new** frame, and no order retro-fills on mount. An actual controller fault pauses with retained values and an explicit Retry at the retained offset; reaching the hard end emits `ended` and freezes the last sample until Reset Demo. Browser network loss alone does neither. The same sample frame carries scenario-time underlying mid and an authored contract mark by contract ID; a missing mark is null and cannot fill. At the host, `useOrderEngine` uses that sample frame and **local simulation eligibility** to admit a non-frozen authored mark without setting `isLive`; the pure `orders/engine.ts` uses a separate `demo_simulation` standing in its trigger/fill predicate instead of recomputing genuine liveness from `LiveUpdate`. Live `tickFromLive`, `computeMark`, `genuineIsLive`, `limitWouldFill` and live transition rules stay intact. All demo create/default-good-til/today/expiry, render-time `useOrders` sweep, tick sweep, cancel/trigger/fill and decision-record timestamps use the controller's scenario clock and Eastern contract-day end; no default `Date.now()`/`new Date()` consumer may expire the Oct 2026 sample on a later host date. The existing shared `TradeEntryDialog` confirmation, forward-only status transitions, per-order isolation and one-position-per-fill still apply; there is no real execution path or new automatic order capability.

**Analysis and research.** The local bars provider supplies 60 ordered, synthetic daily OHLCV observations per supported symbol, with a named interval, USD price units, sample source and anchor. Technical analysis reads only those bars; it does not mutate Market Context, live quant definitions, AI input, score, tier, fingerprint or entry gate. EMA20/50 use closing prices, initial simple-average seed at indices 19/49, then multiplier `2/(window+1)`. True range is `max(high-low, abs(high-previousClose), abs(low-previousClose))`, with the first bar's true range `high-low`; ATR14 is the **simple mean of the latest 14 true ranges**, first available at index 13, in price units. RSI14 uses Wilder smoothed average gains/losses over close changes, first at index 14; both averages zero means RSI 50, loss zero with gain positive means 100. ADX14 uses Wilder-smoothed TR and directional movement, first DI/DX at index 14 and first ADX as the mean of DX indices 14..27 at index 27; zero denominator yields 0 after warm-up. This is the new local series' explicit availability convention; it does **not** claim byte-for-byte warm-up parity with `libs/quant-engine/src/context_pack.rs`, whose helper needs one more close change. G4 uses independent vectors for this convention. Earlier indices are `null` with reason `insufficient_history`, never zero. Flat valid series therefore yield EMA at the flat close, ATR 0, RSI 50 and ADX 0 after their respective warm-ups. Computed readings carry method/window/basis and source-bar IDs; chart and tooltip expose date, units and an accessible non-hover reading. The six Research cases each reference their own scenario/symbol snapshot and provide authored thesis, evidence links into Overview/Technical analysis, possible catalysts, risks, invalidation/assumptions and explicit uncurated vs checked-none facts. No invented external citation, current news, outcome or generated AI response appears.

**Build/deploy and evidence.** Dashboard production target retains route splitting, existing Brotli chunk limits and production optimization; mode, `ANALYZE`, Node runtime and postprocess/helper inputs enter its resolved Nx cache identity. A versioned outer `build:dashboard` wrapper sets `VITE_DATA_MODE=demo` only when `CF_PAGES=1` and `CF_PAGES_BRANCH=codex/portfolio-demo-platform`, unless the caller explicitly supplied a valid mode, and does so **before** spawning Nx. All other branches/ordinary builds keep the live default; an invalid explicit value fails. The Pages project build command points to this wrapper. Private sourcemap output is deterministic or explicitly uncached; no missing archival artifact is claimed restored by a cache hit. Measure demo and live artifact sizes/routes and build durations, then prove demo→demo cache hit→live miss→demo restore with sequential builds. Deploy the verified feature-branch preview through the existing Pages Git integration, without merging to main or touching Railway. Inspect Pages settings and emitted Functions routing before upload; ensure the demo preview is static-only using a supported, verified route configuration in the built artifact (or equivalent Pages setting), while preserving the repository's live `/api` proxy for live builds. Prove the hosted preview makes no API/Function/vendor/broker/OAuth/AI request; do not infer that from the local build. A production demo artifact does not invoke the repository's Railway migration hook, change `apps/api`, or imply a running Rust backend. Atlas source traces are labeled **source-inferred**; local command/browser results **locally observed** with exit codes; deployed URL checks **hosted observed**. Unknown measurements remain `NOT RUN`, not estimated.

**Failure modes + isolation:** Unknown demo operations/symbols return typed unavailable without network. One optional invalid/missing metric withholds only its figure, never turns it into zero or fails the whole bundle. A cold local chunk/catalog failure shows view-level retry and no data; a refresh failure after success retains the last sample with an explicit update-failed label. A stream pause affects moving values only; static bundle, book and analysis remain readable. Unsupported live bars/research show a named unavailable outcome while existing live ticker and book operate normally. A failed storage read preserves bytes and blocks writes to that store, while unrelated views remain available. A blocked static-host chunk may prevent first navigation to an unvisited lazy route; already loaded/cached routes and their sample data remain usable.

**Not buildable / rejected approaches:** A separate pretend site would duplicate the actual app. A backend-wide fixture profile would require auth/store/stream and production guardrail changes. The existing Rust helper is not a full scenario compiler; a lookup keyed only by expiry without dependent signal variants, DTE normalization and explicit null position evaluation would return incoherent data. A global fetch shim misses EventSource and navigation. Reusing the test-account seed would touch live browser keys; using session tape or `live:true` would assert false provenance. Precache-all/PWA would expand the requested scope and landing bytes. None is a dependency of this frontend composition.

**Research case substance.** Each of the six normal Research cases has a distinct authored thesis about that symbol's own bars and selected/full-chain structure, at least two present evidence claims resolving to that case's bar IDs or authored snapshot fields, a distinct risk and a concrete invalidation condition tied to those inputs. Shared synthetic-data limitations may appear as assumptions, but cannot be the entire thesis, risk or invalidation. A catalyst is stated only when authored for this scenario; `uncurated` is never rendered as `checked_none`. The case must not imply news, observed history, a prediction, backtest or model response. Selecting another symbol changes the case and its cited inputs together.

## 4. UI + interaction

**Flows:** Landing/Scanner → six-symbol Ticker Overview → ticker-local Technical analysis/Research → simulated Positions/Orders/Alerts → Settings; one shared paper-entry confirmation and a separate Reset Demo. `/_ops/metrics` and `/_ops/research` stay outside the trader shell and are unavailable in public demo. The four existing global navigation links remain Scanner, Ticker, Positions, Alerts; the new three-view switcher is local to the selected ticker. ## 5. Error handling

- `demo_unsupported` identifies a symbol/expiry/query outside the authored catalog and names supported choices; `demo_unavailable` identifies a capability intentionally absent. Both stop at the local facade with no network fallback. A local operation failure is `error`, logged without keys/portfolio contents, and offers Retry where repeatable.
- Unknown/malformed or corrupt fixture data fails the affected view or field only. Do not coerce `null`, absent, `NaN` or a failed calculation to zero. The original malformed browser storage bytes remain untouched; write refusal is shown at the affected store.
- Cold lazy-chunk or catalog asset failure shows the view error; a restored catalog asset is fetched again by same-document Retry rather than reusing a rejected module load. Failed refresh over ready data retains the last data with a distinct message. A successful later retry clears that message. The shared demo timer stops with zero subscribers, and typed pause/end events retain last prices; pending awaited batches are invalidated on pause/end/cohort change. Actual paused playback marks moving values only. Browser offline status by itself is not proof of playback pause. Reaching the finite end requires Reset Demo to restart, while a controller fault can Retry from its retained offset.
- Auth/OAuth, AI key, broker credential/refresh, operator direct fetch and unknown direct navigation are refused locally in demo with explicit copy. No email/password/key/token is requested or saved. Live routes keep their server-enforced auth and their original error semantics.
- An uncached lazy route can fail to load when static-host assets are unreachable; show the static-asset load error if the shell can render it. Do not present loaded/cached-route usability as whole-site offline installation.
