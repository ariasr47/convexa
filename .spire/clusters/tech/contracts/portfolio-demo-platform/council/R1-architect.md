# R1 — architect position: portfolio-demo-platform

## Position

**Decision and mechanism.** Build a static, browser-composed demo beside the existing live composition. One validated build-time selector (`VITE_DATA_MODE=demo|live`) selects all ordinary HTTP, streams, browser stores, and navigation-to-external-service capabilities before the app mounts. An omitted selector retains today's live behavior; an unknown selector fails the build. Vite bakes the choice into assets, so changing it requires a rebuild and redeploy. Put the selector and build scripts in Nx's effective build inputs, then prove separate cache identities by building demo, live, and demo again. No production Rust mode, database, vendor credential, migration, or Railway release is needed. The static candidate targets the existing Pages project only after its configuration is inspected. [client.ts:5](../../../../../../libs/api/src/lib/client.ts) is the ordinary HTTP choke point; [config.rs:119](../../../../../../apps/api/src/config.rs) shows backend `paused` stops acquisition rather than producing demo data.

**Why this boundary.** A browser adapter has low implementation and hosting cost, scales as static assets plus per-browser state, and follows the team's existing typed facade. A backend demo profile would reuse Rust calculations but needs isolated auth, scanner, streams, stores, and production startup policy; it has greater complexity and operations cost. A separate pretend site duplicates the product and its workflows. The browser option wins on cost and change surface, accepting that the public demo cannot prove hosted Rust execution.

**Data structure.** Use one versioned synthetic scenario catalog with a finite supported-symbol registry, one scenario clock, per-symbol option-chain inputs, precomputed/validated bundle variants, bars, scanner rows and structure history, contract marks, candidate and analysis records, and a distinct simulation book, order history, broker sample book, alerts, personas, and research notes. Identity links and dates must be referentially valid across these families. A scenario compiler can use the existing pure quant path to materialize filtered bundle variants offline; the runtime imports the compiled catalog, never computes a market sweep. Normalize filter requests to an expiry set and optional context inclusion, select the matching precomputed variant, and return a typed unavailable result for an unsupported combination. This is an assumption to challenge if the actual query space is unbounded. [market_data/mod.rs:122](../../../../../../apps/api/src/services/market_data/mod.rs) confirms a fixture port suitable for authoring, not a public production selector.

**Clock and coherence.** On first demo use, store a simulation epoch and seed version before any page/store hydration. Derive sample timestamps, scenario DTE, future expiries, bar positions, scanner history, stream frames, order eligibility, and recommendation grounding from that epoch; playback advances a bounded simulation offset, never independently relabels frozen vendor observations with wall time. Query/filter changes select a coherent catalog variant; a scanner row, ticker bundle, contract quote, bar series, and research assertion for one symbol refer to the same scenario state. Seed only missing demo records. Preserve explicit deletions, malformed original bytes, and read-fault write latches. Reset enumerates demo keys only. The existing test-account seed is unsuitable because it writes the shared live position key and uses fixed 2026 expiries ([testSeed.ts:22](../../../../../../apps/dashboard/src/app/features/trading/positions/testSeed.ts)).

**Provider flow and failures.** Keep existing pages/hooks consuming typed domain operations. At the HTTP transport, dispatch every currently exported operation by method and route to a typed local handler in demo; include the complete 30-call inventory in the frontend audit, including auth/settings, scanner and saved view, ticker/contract/candidates, simulation gate/book, AI status/request/export, personas, broker read/refresh/credentials, and operator metrics. Unknown method/path or symbol fails closed with a typed unsupported response, without network fallback. Handle ticker and scanner EventSource behind a shared subscription interface with independent ownership, bounded playback, teardown, and gap behavior; [convexa.ts:1316](../../../../../../libs/api/src/lib/convexa.ts) and [useLivePrices.ts:57](../../../../../../apps/dashboard/src/app/pages/scanner/useLivePrices.ts) currently construct them separately. Disable or locally satisfy the operator research direct fetch, Google/Grok redirects, and credential writes in demo before those actions can navigate or contact a server; retain operator routes separate from the new public research provider. [researchClient.ts:43](../../../../../../apps/dashboard/src/app/pages/operator-session-archive/researchClient.ts) verifies the direct fetch bypass. A test-only catchall global fetch shim is insufficient because EventSource and navigation bypass it.

**State ownership.** Namespace all current, legacy, migration, first-paint, export, and outcome-source reads under demo mode, not just final writes. This includes positions/decisions/views and touch time, orders, alerts, personas, UI/theme preferences, recent tickers, scanner view, and locally mirrored book. Preserve live migrations byte-for-byte and never let demo resolve a live legacy key. The demo book adapter is local and versioned; the signed-in sync effect must not contact or overwrite the live server. Real session, broker credentials, OAuth, LLM keys, and live position refresh are unavailable capabilities in demo. A local demo identity and simulation authorization never become an access bypass in live mode, where the Rust server gate remains authoritative. [positions/store.ts:60](../../../../../../apps/dashboard/src/app/features/trading/positions/store.ts), [orders/store.ts:19](../../../../../../apps/dashboard/src/app/features/trading/orders/store.ts), and [outcomes/sources.ts:37](../../../../../../apps/dashboard/src/app/features/trading/outcomes/sources.ts) show distinct current/legacy reads.

**Provenance and liveness.** Model source standing as three disjoint categories: synthetic scenario, genuinely live paid feed, and recorded session tape. A timer is only demo playback, never a live feed or archive occupancy. Keep the existing branded paid-live claim false for synthetic frames; introduce a separate local-simulation eligibility decision for simulated order progression if needed. Do not set a fake `live` truth value merely to trigger fills or motion. Static bundle reads survive a stream gap; stream-derived values become stale independently. [liveClaim.ts:52](../../../../../../apps/dashboard/src/app/shared/liveness/liveClaim.ts) rejects tape and offline payloads; [sessionTapeStanding.ts:39](../../../../../../apps/dashboard/src/app/pages/ticker/sessionTapeStanding.ts) separates display from genuine live eligibility. Synthetic research/analysis numbers carry a fixture-to-bundle or fixture-to-bar trace; a missing basis remains unavailable, not zero or an asserted fact.

**Technical analysis and research.** Add a domain-level bar-analysis provider with a dated, ordered OHLCV series, indicator observations, method/window/basis metadata, warm-up/unavailable states, and source standing. The demo arm computes or validates deterministic EMA20/50, Wilder RSI14/ADX14, and existing ATR simple-mean-true-range variants from the *same* bars; flat series and insufficient history have explicit results. Public research uses authored scenario thesis/catalysts/risks tied to the same dated snapshot and carries explicit absence vs checked-none semantics. Live mode returns an honest analysis-unavailable state until a real public bars provider exists: current market-context summary is not candle history, and operator archives are not trader research. Keep research/chart code and per-symbol scenario data behind route-level dynamic imports so landing does not absorb them. There is no scored input from this addition.

**Atlas and build evidence.** Publish the requested backend atlas as source-linked current-state and proposed-state traces, clearly labeling static source inference versus local runtime measurement versus hosted observation. The source audits are inputs, not proof of a running backend. Keep existing Vite page splitting, Brotli budgets, sourcemap handling, and Rust CI gates; add a dashboard-specific Nx mode input and inspect the resolved target. Measure landing and new route chunk weight before setting new budgets. The Nx research notes that the resolved graph does not model the Cargo quant dependency, so affected-only Rust validation would be unsound without explicit inputs; this demo does not need that change. Deploy the verified static artifact through the existing Pages target without invoking Railway's migration hook. Hosted verification must separately inspect the deployed URL and network traffic.

**Binding domain/math constraints.** Demo fixture generation and validation preserve vendor gamma for profile/walls, analytic Black–Scholes gamma for flip (cost-of-carry `r − q`, `r = 4.5%`, payer dividend yield or zero, minimum Greek time `1/365`, nearest zero crossing on spot ±20%/100-point grid with interpolation), dollar GEX `gamma·OI·100·S²·0.01` with calls positive/puts negative, max/min net walls and max gross peak. Vendor signed delta yields DEX `delta·OI·100·S` at synchronized spot. Nearest monthly OPEX max pain and put/call OI ratio stay full-chain; Vol/OI is full-chain and null with no volume or nonpositive OI. DTE/expiry filters shape GEX/DEX structure only. HV uses 30-day daily log-return sample standard deviation annualized by √252; ATM IV averages call/put IV at the nearest ≥7-DTE ATM tenor, with IV/HV rich above 1.10 and cheap below 0.90. IV skew is put minus call IV at ±25 delta (moneyness fallback); term structure uses ATM IV across all expiries with its near-IV flat band. Session VWAP requires ≥10 RTH one-minute bars and volume-weighted ±2σ/3σ bands. Structure spot and display spot remain distinct; paid-live NBBO mid anchors levels/live flip, last trade is display-only. Dark-pool blocks have no reliable side. New public bar analysis cannot redefine these backend computations; if the synthetic source cannot satisfy an invariant, omit that datum with explicit unavailability.

## Risks I see

- Finite precomputed expiry/filter variants may grow quickly or miss legal combinations. Normalize first, bound supported symbols/expiries, split catalogs by symbol, and measure compressed route weight; an uncovered combination must report unavailable rather than return a mismatched bundle.
- Existing liveness is wired into fills and visual motion. If a demo stream uses a truthy paid-live flag, it can create false claims and trigger the wrong order path. A separately typed simulation standing and an adversarial false-live check are required before enabling automatic demo fills; seeded completed/pending orders can demonstrate the workflow initially.
- Local store migration and book sync have multiple entry points. A one-key namespace patch would leak into live history. Require a single storage-key resolver plus an inventory of every direct read/export path and a demo/live round-trip/reset check.
- The current Pages project has an `/api` proxy; a missed direct fetch, redirect, or EventSource could contact Railway even from static assets. A built-demo browser smoke should block and count all API/vendor/OAuth traffic, visit all data surfaces, and fail on any attempted egress. Keep this one journey bounded; budget initially at most eight retained behavior tests/journeys and under 30 seconds additional frontend unit CI.
- Hand-authored options and bars can produce plausible but internally false figures. Generate/validate a small catalog with quant math and known indicator vectors; separate this numeric guard from broad screenshot assertions. Source audit and Nx memo are static findings, not measurements of this feature or hosted proof.

## Assumptions I'm making about the other two lanes

- Product will accept a finite named symbol set and a local simulated identity, with explicit unsupported states outside it, rather than requiring arbitrary symbols or real signup in the public demo.
- Product will accept that live-mode technical-analysis history and public research are unavailable until a real public provider is separately built; summary Market Context and operator archive are insufficient substitutes.
- Product will specify which simulated trade/order actions must execute during playback; seeded orders/history alone may satisfy the portfolio narrative and avoid broad changes to paid-live fill rules.
- UX will make synthetic provenance persistent at every market/analysis decision point and distinguish demo playback from a paid live stream and recorded session tape without relying on color alone.
- UX will define visible unsupported, insufficient-history, stale-stream, uncurated, checked-empty, credential-unavailable, and reset states, and will amend the four-link navigation canon if it adds a public research destination.
- Both lanes will treat operator diagnostics as a separate tool, leaving its token-bearing fetch and route unlinked from trader research.
