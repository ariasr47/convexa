# supply-chain-automation — brief

Goal:            Make Convexa's build and dependency supply chain reproducible, reviewable, and fail-closed: pin supported Node/npm and Rust toolchains; automate intentionally grouped dependency updates; enforce npm and Rust advisory, license, and source policy; scan source/config/container surfaces supported by the selected tools; produce machine-verifiable software bills of materials; and make the normal GitHub gates reject policy drift without changing application runtime, API, scoring, or trader-visible behavior.
Decision impact: N/A — internal production correctness, security, and delivery throughput. Success is observed when the same revision selects the same supported toolchains, dependency changes arrive as bounded reviewable proposals, prohibited advisory/license/source/image conditions fail automation, clean builds produce traceable SBOM artifacts, and no tool silently downgrades or rewrites application dependencies to make a scan green.
Feasibility:     pass — code-grounded 2026-08-22: the repository has npm and Cargo lockfiles, GitHub CI, production container definitions, and zero production npm advisories, but Node is pinned to Current rather than LTS, Rust CI tracks an unpinned stable channel, there is no repository Rust toolchain file or unified advisory/license/source policy, and the development dependency graph reports transitive Nx advisories that must be handled by explicit policy rather than a blind downgrade. The council must verify exact supported versions and the capabilities/limits of each selected scanner before locking implementation.
