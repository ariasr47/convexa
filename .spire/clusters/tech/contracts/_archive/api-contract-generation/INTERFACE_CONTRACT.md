# api-contract-generation — interface contract

**Status:** draft
**Backend impact:** structural contract-authoring and gate change; `NO_WIRE_BEHAVIOR_CHANGE`
**Frontend impact:** generated internal contract types behind the unchanged public `@convexa/api` facade; `NO_UI_CHANGE`

This file is the FE↔BE truth for the migration. The Rust runtime graph owns all methods, paths, request/response/error/event shapes, statuses, meaningful headers, media types, and security declarations. The generated OpenAPI artifact and generated TypeScript must match this inventory, while runtime behavior stays byte/semantics-compatible with the pre-cutover implementation.

## Generation boundary

```text
Axum 0.8.9 runtime handlers + route-owned Serde wire DTOs/response enums
  -> utoipa 5.5.0 + utoipa-axum 0.2.0 shared OpenApiRouter
  -> apps/api/openapi/convexa.openapi.json (OpenAPI 3.1, committed, canonical)
  -> openapi-typescript 7.13.0 paths/operations/components
  -> libs/api/src/generated/schema.ts (committed)
  -> apps/api/openapi/generated-artifacts.manifest.json (committed sentinel + hashes)
  -> openapi-fetch 0.17.0 generic typed ordinary-HTTP client
  -> existing named @convexa/api compatibility facade

generated stream request/event/error types
  -> existing native EventSource lifecycle adapter
```

- TypeScript `5.9.3` compiles the generated/facade boundary.
- `npm run api:contract:generate` is the only canonical write command.
- `npm run api:contract:check` is the only canonical non-writing drift/policy/compile command.
- Both commands are offline after dependency installation. Neither starts a listener/worker, reads production values, contacts a vendor/store, or serves the artifact.
- `@hey-api/openapi-ts`, generated per-operation SDK files, generated SSE transport, public OpenAPI/Swagger endpoints, and consumer deep imports are not part of this interface.

## Generated artifact identification

Inline notice and structured validity are separate obligations:

- `libs/api/src/generated/schema.ts` is the only current comment-capable generated source. It begins at byte zero with exactly:

  ```ts
  // Generated from the Rust API contract. Do not edit this file.
  // Regenerate: npm run api:contract:generate
  // Check drift: npm run api:contract:check
  ```

- `apps/api/openapi/convexa.openapi.json`, `apps/api/openapi/parity-coverage.json`, and `apps/api/openapi/precutover-operation-baseline.json` remain valid JSON with their exact contracted schemas. No notice is prepended and no generated-marker field is added.
- Any future non-comment-capable or non-text artifact also remains in its native format and is identified only through the same manifest.

The one sentinel/manifest is `apps/api/openapi/generated-artifacts.manifest.json`. `tools/api-contract.mjs` owns and writes it; the baseline accept command owns only the baseline bytes named inside it. The manifest is canonical UTF-8 JSON with lexically ordered keys, path-sorted entries, and one trailing newline. It contains exactly:

| Field | Required value |
|---|---|
| `schema_version` | Integer `1`. |
| `notice` | `Generated from the Rust API contract. Do not edit generated artifacts.` |
| `regenerate_command` | `npm run api:contract:generate`. |
| `check_command` | `npm run api:contract:check`. |
| `owner` | `tools/api-contract.mjs`. |
| `artifacts[]` | Path-sorted entries; no missing, extra, or duplicate path. |

Every `artifacts[]` entry has exactly `path`, `kind`, `media_type`, `sha256`, and `writer`. `kind` is one of `comment-capable-source`, `structured-json`, or `non-text`; `sha256` is lowercase 64-hex over the artifact's exact final bytes. The initial set is:

| Path | Kind | Media type | Writer |
|---|---|---|---|
| `apps/api/openapi/convexa.openapi.json` | `structured-json` | `application/json` | `npm run api:contract:generate` |
| `apps/api/openapi/parity-coverage.json` | `structured-json` | `application/json` | `npm run api:contract:generate` |

The manifest does not list/hash itself, so no cyclic hash exists; canonical generate/check independently regenerates and byte-compares its exact bytes. Generation validates artifact schemas/native formats first, computes final-byte hashes, verifies the exact path set, and installs the mutable outputs with the manifest last; failure restores the prior complete mutable set and never rewrites the baseline. Check validates exact manifest and entry key sets, constants, ordering, kinds/media/writers, path-set equality, and hashes; checks the three-line header only for comment-capable source; rejects comments/plaintext or uncontracted fields in structured JSON; scans all listed bytes plus the manifest; and refuses any missing, extra, unlisted, reclassified, or mismatched artifact. Future non-text output requires a manifest entry with its real media type before generation/check can pass.

Before the runtime router is converted to the shared typed graph, a repository-owned Rust registration parser independently captures the existing production `apps/api/src/routes/mod.rs`. It parses literal `.route()` registrations and recognized Axum GET/POST/PUT/DELETE method-router combinators, including multiline/chained calls, and refuses dynamic/unsupported syntax. It does not import the future OpenAPI artifact and does not accept a handwritten route list.

The sole committed baseline is `apps/api/openapi/precutover-operation-baseline.json`, owned by the Convexa API contract owner and reviewed as interface behavior. Its exact schema is:

Commands and write authority:

- `npm run api:contract:baseline:candidate -- --source-revision <full-40-hex-sha> --out <temporary-path>` captures a candidate and never writes the committed baseline.
- `npm run api:contract:baseline:accept -- --initial --candidate <temporary-path> --review-contract .spire/clusters/tech/contracts/api-contract-generation/INTERFACE_CONTRACT.md --reason api-contract-generation-precutover --reviewer-provenance <review-record>` is the one initial writer. It is allowed only when the baseline is absent, the source/hash/provenance checks pass, and the candidate is set-equal to this 52-row inventory.
- With an existing baseline, acceptance requires `npm run api:contract:baseline:accept -- --candidate <temporary-path> --review-contract <approved-interface-contract> --reason <non-empty-reason> --reviewer-provenance <review-record>`. The reviewed interface must contain `API_BASELINE_CHANGE_APPROVED: <candidate-sha256>` plus the exact added/removed method/path pairs. The command validates them and atomically records `reviewed-behavior-change` provenance.
- `npm run api:contract:generate`, `npm run api:contract:check`, CI, builds, and releases have read-only baseline access. They must never create, update, normalize, or accept it.

For this feature, the post-migration runtime set, OpenAPI set, `parity-coverage.json` operation set, interface table, and immutable initial baseline must all equal the same 52 pairs. Both canonical commands reject missing or extra pairs as `incomplete contract coverage`. The anti-vacuity proof deletes one pair from runtime and OpenAPI together while retaining the baseline; the check still fails with the missing pair, then passes after restoration. A future deliberate endpoint change requires the explicit reviewed accept flow above and a behavior-change review; regeneration alone cannot redefine the baseline.

## Schema and behavior rules

- Every JSON request, success, and declared error has a concrete schema. A truly free-form document, HTML, redirect, or bodyless case must be present in a closed set-equality policy catalog; it is not omitted.
- Every operation declares all real success and non-success statuses, meaningful headers, media types, and its exact security mode. Generic catch-all errors cannot erase known validation, authentication, authorization, conflict, not-found, rate-limit, upstream, or unavailable distinctions.
- A value always serialized as `null` is required-and-nullable; a Serde-omitted value is optional. Empty collections remain different from absent/unknown/inapplicable states. Dynamic keyed values are typed maps.
- Session-cookie, OAuth-state, and operator-token schemes never contain token/cookie values, secret defaults, runtime examples, production origins, or machine paths.
- Ordinary HTTP uses one same-origin `openapi-fetch` client behind `@convexa/api`; browser cookie transport remains browser-owned. The facade preserves current errors, null-on-specific-status handling, abort/coalescing, and named exports.
- SSE OpenAPI entries own the request, event DTO, pre-stream JSON failures, `text/event-stream` media type, and meaningful headers. Native `EventSource` owns browser open/consume/close/reconnect/heartbeat behavior only and imports generated types. Generated TypeScript provides compile-time types, not runtime `JSON.parse` validation.
- Operator/research operations may be generated but remain unlinked and uninvoked from trader flows. No generated/public docs route is served.
- No operation in this inventory may change behavior under this feature. Any intended wire change requires a GATE-Z amendment to both design artifacts before implementation.

## Generated/manual boundary

| Boundary | Generated / Rust-derived | Handwritten but allowed |
|---|---|---|
| Ordinary HTTP | Paths, parameters, bodies, responses, errors, security, `paths`/`operations`/`components`, typed `openapi-fetch` call | Named facade functions, semantic error/null adaptation, abort and request coalescing; no wire declarations |
| SSE | Path/query, event DTO, pre-stream errors, media type, response headers | Native EventSource open/consume/close/reconnect/heartbeat/malformed-event lifecycle only |
| Cookies | Security scheme, cookie-bearing response headers, typed bodies | Browser transport of HTTP-only cookie; facade neither reads nor synthesizes it |
| HTML/redirect/bodyless | Operation, status, media type, meaningful headers | Runtime body/redirect mechanics represented by the typed route response |

The manual exception catalog is set-equality pinned. The initial approved lifecycle entry is `GET /api/stream/{ticker}` at the existing `@convexa/api` native EventSource adapter. A new entry, typed HTTP fallback, generated deep import, or duplicate migrated wire declaration fails the normal check.

## Error and compatibility semantics

The canonical check's closed result categories are `contract drift`, `missing output`, `zero-operation output`, `unsupported schema construct`, `incomplete contract coverage`, `invalid OpenAPI artifact`, `generation tooling failure`, and `generated-client compilation failure`. Only completed byte comparison may say stale/match. Diagnostics expose only safe repo-relative paths/identifiers/stages and the recovery action.

Behavioral compatibility is executable in two tiers. Every source-derived material response boundary executes a production-owned route/source registry entry through the actual Axum response-conversion path and checks its persisted pre-cutover envelope; direct HTTP through the production Tower/Axum router is risk-tiered but includes every source-derived operation and the required access, body, effect, transport, isolation, and shared-error families. Exact DTO schemas remain independently enforced by the route-owned Rust DTO/`IntoResponses` → deterministic OpenAPI → generated-TypeScript graph. Authentication, cookie effects, SSE lifecycle/drop behavior, absent/null/empty meaning, redirect/HTML behavior, operator/trader isolation, public import compatibility, and score/tier/fingerprint identity retain independent evidence.

Rollback restores the matching Rust contract, OpenAPI artifact, generated TypeScript, and public facade together, then passes the canonical check. Artifact-only rollback is invalid drift. No persisted data migration occurs.

## Two-tier executable parity coverage artifact

`apps/api/openapi/parity-coverage.json` is the machine-checkable preservation oracle. It is generated from `apps/api/openapi/convexa.openapi.json` and checked by `npm run api:contract:check`; contributors do not type a second method/path inventory. The current canonical OpenAPI derives 52 operations and 181 material response boundaries. Those numbers describe this reviewed snapshot only: generation derives the authoritative sets, and a future approved baseline evolution must change them through the reviewed contract flow rather than a hand-maintained count.

Its exact top-level fields are:

| Field | Required value |
|---|---|
| `schema_version` | Integer `2`. |
| `source.openapi` | `apps/api/openapi/convexa.openapi.json`. |
| `source.sha256` | SHA-256 of the exact canonical OpenAPI bytes used to derive the keys. |
| `operation_count` | Derived count equal to `operations.length` and the accepted baseline; `52` for this feature. |
| `risk_classes` | Set-equal to `success-json`, `declared-error-json`, `auth-denial`, `cookie-set-or-clear`, `redirect`, `html-or-empty-body`, `sse-stream`, `null-absent-empty`, `operator-trader-isolation`. |
| `evidence_modes` | Set-equal to `response-conversion`, `direct-http`. |
| `operations[]` | Exactly one source-derived entry for every OpenAPI operation identity, method, and path. |
| `operations[].boundaries[]` | Exactly one source-derived entry for every declared `(status, media type or no-body, security mode)` combination for that operation. |
| `runtime_router_boundaries[]` | Closed direct-HTTP rows for fallback/not-found and implicit-method runtime behavior that OpenAPI does not invent as operations. |
| `evidence_catalog[]` | Unique executable evidence rows in exactly one closed evidence mode. |
| `normalizer_catalog[]` | Unique normalizer ID, explicit JSON pointers, comparison rule, and rationale. Empty is valid. |
| `http_parity` | A generated direct-HTTP scenario projection whose operation references resolve to `operations[].key`; it contains no separately authored operation inventory. |

Every operation boundary contains `boundary_id`, `status`, `media_type` (`null` for no body), `security_mode`, non-empty `risk_classes`, exactly one `response_conversion_evidence` ID, a static `body_schema_signature`, and `normalizers` (possibly empty). `boundary_id` is the canonical concatenation of operation identity, uppercase method, path, status, media type/no-body, and security mode; it is derived, not authored. The response-conversion registry-source, persisted-signature, evidence-ID, and emitted-outcome sets are each bijective with the derived boundary-ID set: one unique source-owned envelope case per unique boundary and no ID shared across boundaries. The current derived set has 181 boundaries, but the checker compares sets rather than trusting that literal count.

Every evidence row contains the exact common fields `id`, `mode`, `command`, `target`, `test`, `case_id`, `fixture`, `setup_fixture`, `request_fixture`, `expected_response`, and `effect_assertion`. The named command must execute the named test and case, and that execution must assert and emit an outcome keyed by the same evidence ID; a row that merely points at a source file or fixture without a matching executed outcome fails. `expected_response` contains exact envelope fields: status, meaningful header names and values or value-policy where secrets prevent literals, media type/no-body, body category, valid representative body, and security binding. `effect_assertion` contains explicit pre/post durable, memory, and cookie expectations; `none` is an asserted value, not an omission.

For `mode: response-conversion`, the row also contains exactly one derived `boundary_id`, a repo-relative `source_registry_target`, an independent `persisted_signature_id`, and `production_path` naming `IntoResponse` or the extractor-response conversion. Its `request_fixture` is the source-registry constructor/rejection input. The production-owned registry lives with the route/source boundary, constructs a valid representative Axum response for that persisted signature through the actual production conversion trait, and observes the exact expected envelope/effect. Neither the registry nor its executing collector may read committed or candidate OpenAPI; only after execution does the checker compare registry/source/signature/evidence/outcome IDs to the independently OpenAPI-derived material-boundary set. Missing, extra, duplicate, drifted, comment-only, metadata-only, or unknown registry entries fail. Static OpenAPI inspection, replaying prewritten response bytes, or relabeling one fabricated response is not executable response-conversion evidence.

This exhaustive tier proves response envelopes, not exact typed DTO bytes. Exact body schemas are proven by route-owned Rust DTO and `IntoResponses` definitions feeding deterministic OpenAPI, per-boundary `body_schema_signature` mutations, generated TypeScript, and strict consumer compilation. Risk-tiered direct-HTTP cases additionally assert actual body shapes for the high-risk scenarios. A representative JSON/text/SSE body in the envelope registry must never be described as exact DTO parity.

For `mode: direct-http`, the row also contains one source-derived `operation_key` (or one closed runtime-router key), a unique `scenario_id`, an exact hermetic request, `coverage_tags`, and any `shared_mapping_family`. The request is sent through the actual Tower/Axum production router created from `contract_router()`; its outcome asserts the actual body shape, exact response envelope, and pre/post durable, memory, and cookie effects. `http_parity.scenarios[]` contains only references/projections of these direct-HTTP rows. The checker derives its operation-key vocabulary from `operations[]`, requires at least one distinct scenario for every operation, and rejects a second authored 52-route map, an unknown operation key, or the same request/outcome relabeled as another operation or mapping family.

The direct-HTTP coverage tags and corresponding executed outcomes must collectively prove:

- at least one actual router request for each source-derived operation;
- public valid plus applicable validation/upstream/fault behavior; optional-session anonymous and authenticated success plus invalid/refusal behavior; required-session success plus unauthenticated/forbidden refusal; OAuth valid and invalid state; and operator-token success plus denial, so every access mode has positive and negative direct-HTTP observation;
- every cookie-bearing and mutating route's success plus applicable refusal, validation, or conflict, with pre/post durable, memory, and cookie effects;
- OAuth redirect/cookie behavior; operator/research success, denial, not-found, and fault; SSE stream/open, validation, drop, capacity, and pre-stream JSON; and operator/trader isolation; and
- representative shared production mapping families for `400`, `401`, `403`, `404`, `409`, `422`, `500`, `502`, and `503`.

A generic `500`, `502`, or `503` mapping repeated across handlers may use one direct-HTTP observation for each shared production mapping family because each declared operation-boundary still has independent response-conversion envelope evidence. This allowance never permits one request to be relabeled as another operation or mapping family. AC-25 remains direct HTTP: successful, unauthenticated, forbidden, conflicting, and non-enumerating outcomes retain exact state effects.

Every evidence ID resolves exactly once and every catalog entry is referenced and observed. The checker enforces equality among derived operation/boundary/runtime-only keys, response-registry source IDs, persisted-signature IDs, artifact references, catalog IDs, implemented case IDs, and emitted outcome IDs; it rejects missing, extra, duplicate, unknown, unused, drifted, comment-only, metadata-only, unexecuted, or evidence-mode-mismatched values. Negative mutations independently remove, add, duplicate, drift, mis-mode, comment out, reduce to metadata, or redirect each class of key/reference/outcome; replace a real case with an unexecuted fixture row; and relabel a direct request. Every mutation fails the check or named parity command, and restored controls pass.

The sets of referenced, catalogued, and implemented normalizer IDs must be equal; unused/unknown normalizers fail. Normalizers use explicit JSON pointers only and may normalize genuinely nondeterministic values, never field presence, null/empty meaning, status, meaningful headers, media type, security, cookie effects, or durable/memory effects.

`libs/api/README.md` links this artifact beside the live conformance instructions and states the hierarchy: response-conversion evidence exhaustively preserves envelopes over the source-derived material boundary set; the Rust DTO/`IntoResponses` → OpenAPI → TypeScript graph preserves exact schemas; direct HTTP is risk-tiered but operation-complete and asserts actual high-risk bodies/effects; and the `## Conformance spec` below is only a four-call live JSON smoke check. It cannot substitute for these proofs. Any displayed count is read from the generated artifact rather than maintained as an endpoint catalog.

The README and every `api:contract:check` summary emit this exact warning: `Coverage note: the four-call live conformance block is supplementary; response-envelope conversions are exhaustive, typed schemas are enforced through the Rust-to-OpenAPI-to-TypeScript graph, and direct HTTP evidence is risk-tiered across every source-derived operation.`
