# api-contract-generation — brief
Goal:            Make the Rust API the executable source of truth for its HTTP contract: generate a deterministic OpenAPI artifact from route/request/response definitions, generate checked TypeScript types and client functions from that artifact, migrate the shared `@convexa/api` boundary to consume the generated output, and make any backend/client drift fail the normal repository gates. Preserve current endpoint behavior, authentication semantics, SSE behavior, and trader-visible UI.
Decision impact: N/A — production-maturity tooling. Improves correctness and delivery throughput by replacing hand-maintained Rust↔TypeScript duplication with one machine-checked contract; observed when a deliberate backend wire change produces a deterministic spec/client diff and an unregenerated change fails CI.
Feasibility:     pass — code-grounded 2026-08-22: Axum registers the HTTP surface in `apps/api/src/routes/mod.rs`; `libs/api/src/lib/convexa.ts` and `broker.ts` currently hand-maintain response types and fetch functions; no Rust OpenAPI/schema-generation dependency is present. The council must choose and verify the Rust schema/route mechanism, generation boundary, SSE/error/cookie representation, and migration strategy before implementation.
