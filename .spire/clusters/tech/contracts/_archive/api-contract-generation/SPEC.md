# api-contract-generation — spec

**Status:** draft

## 1. Goal + scope

Make the Rust HTTP boundary the executable source of truth for Convexa's API contract. The runtime Axum route graph will also emit one deterministic, committed OpenAPI 3.1 artifact; that artifact will generate checked TypeScript contract types consumed behind the existing `@convexa/api` facade. Local, CI, build, and release gates fail closed when the Rust graph, OpenAPI artifact, generated types, or public facade disagree. This is developer and release tooling: all current HTTP, authentication, cookie, SSE, scoring, operator/trader isolation, and trader-visible behavior stays unchanged.

**In scope:**

- One source-derived inventory for all 52 method/path operations currently registered by the production Axum router, including aliases, JSON, HTML, redirects, SSE, operator/research, and currently unconsumed surfaces.
- Pinned Rust-to-OpenAPI and OpenAPI-to-TypeScript generation, deterministic committed outputs, policy validation, drift checking, safe diagnostics, negative artifact scanning, and normal-gate integration.
- Explicit route-owned request, response, error, event, parameter, security, cookie, header, and media-type schemas at the HTTP boundary.
- Migration of `@convexa/api` wire authority to generated `paths`, `operations`, and `components`, while preserving its existing named exports and semantic behavior.
- Browser-native `EventSource` lifecycle retained as the sole approved manual transport class; its request/event/error DTOs remain generated.
- A two-tier executable preservation proof: exhaustive production response-conversion evidence for every source-derived material response boundary, plus risk-tiered direct HTTP evidence through the production router with every inventoried operation accounted for.
- Contributor documentation, exact terminal result vocabulary, atomic generation, rollback guidance, and non-vacuous rejecting/accepting gate proofs.

**Out of scope:**

- GraphQL, microservices, API redesign/versioning, generated Rust servers, schema registries, public SDK publication, public Swagger/Redoc/Scalar routes, or runtime code generation.
- New endpoints, changed methods/paths/statuses/headers/bodies, authentication or cookie-policy changes, SSE cadence/reconnect changes, runtime payload validation, persisted-data migrations, or deployment configuration.
- Any scoring, tier, gate, fingerprint, quant-math, trader-copy, navigation, layout, loading, offline, or visual change.
- Supply-chain automation, capacity baselining, remote archive bodies, telemetry/SLOs, replica-safe workers, recovery automation, or later resilience slices.

**Future (deliberately deferred):**

- Breaking-change/versioning policy, external documentation/SDKs, other generated languages, runtime schema validation, or a separately approved SSE transport redesign.
- Generator-upgrade automation and advisory policy beyond the exact audited pins in this slice.

## 2. Architecture

### Proven generation chain and ownership

The binding toolchain is Axum `0.8.9` + `utoipa` `5.5.0` + `utoipa-axum` `0.2.0` → deterministic committed OpenAPI 3.1 JSON → `openapi-typescript` `7.13.0` contract types + `openapi-fetch` `0.17.0` generic typed HTTP client behind the existing named `@convexa/api` facade, compiled with TypeScript `5.9.3`. Exact Cargo/npm pins and lockfiles are part of the contract. The clean compatibility spike compiled this graph, exported byte-identical OpenAPI twice, generated byte-identical TypeScript offline twice, strictly compiled JSON and native-EventSource consumers, and found zero production-dependency audit findings in the tested lock tree. `@hey-api/openapi-ts`, a per-operation generated SDK, and generated SSE transport are rejected for this slice because the tested Hey API tree had four high-severity findings and the clean chain already satisfies the required boundary.

### One runtime and contract graph

`apps/api/src/routes/mod.rs` becomes a pure `contract_router()` that returns `utoipa_axum::router::OpenApiRouter<AppState>`. It registers each handler in the spike-proven form of one `.routes(routes!(handler))` call per operation. Runtime startup converts the router half and attaches the already-built `AppState`; a small exporter under `apps/api/src/bin/` takes the OpenAPI half without constructing state, reading environment values, starting workers/listeners, touching vendors/stores, or using the network. The runtime and artifact therefore cannot acquire separate route lists.

The exporter derives the production operation inventory from that same graph. Every one of the 52 current method/path operations in `INTERFACE_CONTRACT.md` appears exactly once with a stable unique operation identity. Closed classifications account for JSON, HTML, redirect, bodyless, SSE, operator/research, and alias surfaces without excluding them from OpenAPI. Framework fallback/not-found behavior and implicit method behavior are tested against the runtime router but are not invented as OpenAPI operations. A missing/duplicate identity, absent inventory row, extra runtime operation, or missing required response/security/media shape is `incomplete contract coverage` and fails the check.

Before `routes/mod.rs` is converted to `OpenApiRouter`, `npm run api:contract:baseline:candidate -- --source-revision <full-40-hex-sha> --out <temporary-path>` independently parses the existing production router's Rust registration expressions and emits a sorted candidate. `npm run api:contract:baseline:accept -- --initial --candidate <temporary-path> --review-contract .spire/clusters/tech/contracts/api-contract-generation/INTERFACE_CONTRACT.md --reason api-contract-generation-precutover --reviewer-provenance <review-record>` is the sole writer of `apps/api/openapi/precutover-operation-baseline.json`. The capture records the exact observed 52 uppercase method/path pairs, the committed source revision, `apps/api/src/routes/mod.rs` SHA-256, capture-tool path/hash/parser version, UTC capture time, commands, count, and initial-review provenance. The Rust registration parser accepts literal `.route()` paths and recognized Axum method-router combinators, including chained methods and multiline calls; it refuses dynamic/unsupported syntax instead of silently skipping it.

The committed baseline is independent of the later shared runtime/OpenAPI graph and is immutable to both canonical generate and check commands. Both commands compare the post-migration runtime inventory, canonical OpenAPI inventory, and parity-coverage operation inventory separately against the baseline's method/path set and fail `incomplete contract coverage` on any missing or extra pair. A mutation test deletes one operation from the post-migration runtime and OpenAPI together while leaving the baseline untouched; the normal check must still fail with that missing pair, then pass after restoration. This closes the co-omission case where runtime and documentation could otherwise agree on the same accidental deletion.

Future endpoint changes do not overwrite the preservation baseline during ordinary generation. A reviewer first approves a behavior-changing `INTERFACE_CONTRACT.md` containing `API_BASELINE_CHANGE_APPROVED: <candidate-sha256>` and exact added/removed pairs; only then may the API contract owner run `npm run api:contract:baseline:accept -- --candidate <temporary-path> --review-contract <approved-interface-contract> --reason <non-empty-reason> --reviewer-provenance <review-record>`. The accept command verifies candidate/source hashes, review marker, pair diff, reviewer provenance, and a clean baseline diff before atomically replacing the file. The current feature permits no pair change: its post-migration set must equal the initial 52-pair baseline.

Preservation uses two complementary executable tiers. Static inspection of generated OpenAPI is never parity evidence, and a fixture row or evidence label that no named test actually constructs and observes is rejected.

The exhaustive tier is `response-conversion` envelope evidence. A production-owned registry lives with the route/source boundary and is independent of generated OpenAPI. For each independently persisted pre-cutover boundary signature, the registry uses the source-owned response builder or rejection conversion to construct a valid representative Axum response, invokes the actual `IntoResponse` or extractor-response path, and asserts the exact status, contract-meaningful header set/value policy, media type or no-body state, body category (`json`, `text`, `html`, `empty`, `sse`, or `redirect`), valid representative body, and security binding. The observed conversion side may not read committed or candidate OpenAPI. After execution, the checker independently derives canonical material boundary keys from OpenAPI as `(operationId, method, path, status, media type or no-body, security mode)` and requires the registry IDs/source targets, persisted signature IDs, evidence rows, and emitted outcomes to be set-equal; the current reviewed artifact derives 181 keys, but the derived set—not that prose count—is authoritative. Table- or macro-driven execution is allowed only when the run emits and asserts an independently identifiable outcome for every evidence ID. Missing, extra, duplicate, drifted, comment-only, or metadata-only registry entries fail. A generic error family repeated on many operations therefore receives executable envelope evidence at every declared boundary; static schema comparison or one fabricated response reused under many labels does not satisfy this tier.

Response-conversion envelope evidence does not claim that a representative body proves every typed DTO byte or schema. Exact request/response/error/event body authority remains the route-owned Rust DTO and `IntoResponses` graph → deterministic OpenAPI → generated TypeScript compile. Per-boundary schema-signature mutations prove that this graph rejects typed-schema drift, while risk-tiered direct HTTP scenarios assert actual body shapes for the high-risk authentication, cookie, mutation, OAuth, operator/research, SSE, isolation, and shared-error cases.

The risk-tiered tier is `direct-http`. It sends real requests through the actual Tower/Axum production router built from `contract_router()`, with at least one scenario for every one of the 52 source-derived operations. Its scenario matrix covers public and optional-session behavior, required-session success and refusal, OAuth valid/invalid state with redirect/cookie effects, operator-token success/denial/not-found/fault, all cookie-bearing and mutating routes with success plus applicable refusal/validation/conflict and pre/post durable/memory/cookie effects, SSE open/stream/validation/drop/capacity/pre-stream JSON behavior, operator/trader isolation, and representative shared `400`, `401`, `403`, `404`, `409`, `422`, `500`, `502`, and `503` mapping families. A generic fault status shared by multiple handlers may use one direct-HTTP observation per shared production mapping family because every declared operation-boundary still has its own response-conversion envelope evidence. Relabeling an identical request as another operation, scenario, or mapping-family observation is prohibited.

The machine-checkable binding is the committed `apps/api/openapi/parity-coverage.json`. The checker derives expected operation and boundary keys from canonical OpenAPI plus runtime-only fallback/implicit-method probes; `http_parity` contains scenario references to those derived operation keys and is not another authored 52-route map. Evidence rows use exactly one of the closed modes `response-conversion` or `direct-http` and resolve to a runnable repository command, named test and case/outcome, fixture, setup, request or constructor input, expected response, and exact effect assertion. The checker enforces equality across derived keys, references, catalog rows, implemented cases, and observed outcomes; missing, extra, duplicate, unknown, unused, or mode-mismatched values fail. Runtime-only fallback/implicit-method rows are direct HTTP and must likewise match an executed outcome.

Normalizers live in a closed catalog containing an ID, explicit JSON pointers, comparison rule, and rationale. The referenced normalizer-ID set, catalog-ID set, and implemented normalizer-ID set must be equal; every normalizer is used, no wildcard pointer is allowed, and no normalizer may remove field presence, null/empty meaning, status, contract-meaningful headers, media type, security, cookie effects, or durable/memory effects. Negative mutations prove rejection for each evidence mode, missing/extra/duplicate/unknown rows, unmatched test/outcome references, and relabeled direct requests before restored controls pass. The exhaustive claim applies to response conversion; direct HTTP is risk-tiered but operation-complete. The four live conformance calls in `INTERFACE_CONTRACT.md` are only a supplementary smoke check.

### Rust wire authority

Route-owned wire DTOs live under `apps/api/src/routes/` and derive Serde plus the corresponding utoipa schema/parameter traits. Domain and service types remain independent of HTTP/OpenAPI; `libs/quant-engine` gains no OpenAPI dependency. Route-owned response contract types implement utoipa `IntoResponses`; handlers return `RouteResponse<R>`, which wraps the production-built Axum `Response` at runtime while binding `R` as that handler's OpenAPI response set. The pinned `auto_into_responses` mechanism must bind the handler's concrete `RouteResponse<R>` return type to the emitted response set, with a mutation that makes build/check fail. Runtime envelope drift is caught by the independent response-conversion registry and direct HTTP tiers; typed body-schema drift is caught by the Rust DTO/`IntoResponses` → OpenAPI → TypeScript chain. Broadly refactoring every handler to construct a typed runtime enum is not required and is outside this preservation slice; handwritten parallel OpenAPI response lists remain prohibited.

Handler-level unconstrained JSON request/success/error/event bodies are removed. Required-versus-optional follows actual Serde emission: always-present nullable values remain required-and-nullable; omitted values are optional. Dynamic dictionaries use typed map values. Closed state vocabularies preserve unknown/empty/inapplicable meanings. A narrow set-equality-pinned policy catalog may classify truly free-form documents, HTML, redirects, or bodyless operations, but cannot hide a typed HTTP wire shape.

Security schemes express session-cookie, operator/research token, OAuth-state, public, and optional-session modes without embedding secret values. Session creation/clearing declares `Set-Cookie`; redirects declare `Location`; SSE declares `text/event-stream`, its data-event DTO, pre-stream JSON errors, and contract-meaningful headers. Server checks remain authoritative even when the generated client declares security.

### TypeScript boundary and the sole manual transport class

The committed OpenAPI artifact lives at `apps/api/openapi/convexa.openapi.json`. `openapi-typescript` emits `libs/api/src/generated/schema.ts`; `openapi-fetch` provides the generic typed ordinary-HTTP client. `libs/api/src/index.ts`, `libs/api/src/lib/convexa.ts`, and `libs/api/src/lib/broker.ts` remain the stable semantic facade: they preserve current function names, error classes, same-origin credentials, abort/coalescing behavior, special null/not-found adaptations, and public return shapes while importing generated wire types and delegating ordinary HTTP calls through the typed client.

Consumers import only `@convexa/api`. A TypeScript-AST check rejects dashboard deep imports from generated internals and migrated request/response/error/event wire declarations outside generated output. The facade may contain semantic adapters, but it cannot redeclare wire shapes or cast arbitrary JSON into contract types. `Migration complete` means the contract check, duplicate-authority/import check, affected builds, and consumer tests all pass.

OpenAPI is unconditionally authoritative for SSE request parameters, media type, data-event DTO, pre-stream errors, and meaningful headers. The existing native `EventSource` adapter remains authoritative only for browser open/consume/close/automatic-reconnect/heartbeat/malformed-event isolation. Its generated-type-backed entry for `GET /api/stream/{ticker}` is set-equality pinned in the manual-boundary catalog and owns lifecycle parity evidence. No generator failure may add another manual typed HTTP fallback.

### Deterministic, atomic, offline artifacts

The canonical commands are `npm run api:contract:generate` and `npm run api:contract:check`. A repository-owned orchestrator under `tools/` invokes the pure Rust exporter, canonicalizes maps lexically, emits pretty UTF-8 JSON with one fixed trailing newline, validates OpenAPI, runs schema/inventory/security/media policy, generates TypeScript into a temporary directory, applies one deterministic source-header postprocessor, writes one deterministic generated-artifact sentinel/manifest, strictly compiles the generated/facade boundary, performs the artifact-content scan, and atomically replaces mutable outputs only after every stage succeeds. The check command runs the same pipeline in a temporary directory and byte-compares the OpenAPI, parity, TypeScript, and sentinel/manifest bytes without modifying committed output.

After declared dependencies are installed, both commands run with zero network access; connectivity belongs only to dependency bootstrap. Time, git SHA, environment values, runtime examples, random identifiers, production origins, and machine paths never enter the ordinary OpenAPI, parity, TypeScript, or sentinel/manifest outputs. The independently accepted pre-cutover baseline is the sole intentional provenance exception: it records its already-contracted capture revision/time/hash and remains immutable to these commands.

Only comment-capable generated source files receive an inline header. Currently that set contains only `libs/api/src/generated/schema.ts`, whose byte zero begins this exact three-line TypeScript-comment header followed by one newline before generated code:

```ts
// Generated from the Rust API contract. Do not edit this file.
// Regenerate: npm run api:contract:generate
// Check drift: npm run api:contract:check
```

Structured JSON, non-comment-capable text, and non-text artifacts never receive prepended comments/plaintext and never gain uncontracted fields. One sentinel/manifest at `apps/api/openapi/generated-artifacts.manifest.json`, owned and written only by `tools/api-contract.mjs`, identifies them. Its canonical JSON schema has exactly `schema_version` (`1`), `notice` (`Generated from the Rust API contract. Do not edit generated artifacts.`), `regenerate_command` (`npm run api:contract:generate`), `check_command` (`npm run api:contract:check`), `owner` (`tools/api-contract.mjs`), and path-sorted `artifacts[]`. Each artifact entry has exactly `path`, `kind` (`comment-capable-source`, `structured-json`, or `non-text`), `media_type`, lowercase 64-hex `sha256`, and `writer`. The initial set contains `convexa.openapi.json`, `parity-coverage.json`, `precutover-operation-baseline.json`, and `schema.ts`; their writers are respectively the canonical generate command, canonical generate command, baseline-accept command, and canonical generate command. The manifest does not hash itself, avoiding a cycle; its exact canonical bytes are independently regenerated and byte-compared.

Generation first validates each candidate against its own contract, computes hashes over exact final bytes, verifies the manifest path set is exact, then installs the mutable artifact set with the manifest last; any installation failure restores the prior complete mutable set. Check validates the manifest's exact key sets, constants, path order, path-set equality, kinds/media types/writers, and hashes; verifies the TypeScript header only on `comment-capable-source`; validates structured JSON without comments or extra sentinel fields; scans every listed artifact plus the manifest; regenerates the manifest; and rejects missing, extra, reclassified, unhashed, mismatched, or unlisted output. A future non-text output must be listed with its real media type before generation can pass.

The normal API tests, `@convexa/api` typecheck/tests, root `npm run ci`, production build, and release gate invoke `api:contract:check`. Mutation tests poison the runtime contract, committed OpenAPI, generated tree, inventory coverage, exception catalog, duplicate-authority boundary, and artifact-content policy; each poison must make the gate red, and its restored control must pass.

The artifact-content scan is explicit and bounded to the committed OpenAPI/generated paths. It rejects forbidden credential literals, credential-like values copied from the environment, configured production origins, and Windows/POSIX absolute machine paths. It does not claim an unverified repository-wide secret scanner.

**Failure modes + isolation:** Generation/checking is build-time only and has no runtime fallback. Any failed stage retains the last committed bytes, writes no partial output, exits non-zero, and prevents build/release acceptance; it cannot affect a running route, store, vendor, worker, or trader session. Runtime schema generation and production documentation routes do not exist. Generated compile-time types do not claim runtime validation; malformed SSE event isolation remains unchanged.

**Not buildable / rejected approaches:** Hand-authored OpenAPI or a second operation list; untyped JSON bodies for typed HTTP shapes; handwritten ordinary-HTTP fallbacks; direct dashboard imports of generated files; `@hey-api/openapi-ts`; generated per-operation SDK/SSE transport; OpenAPI Generator's Java/container toolchain; runtime generation; public documentation endpoints; artifact-only rollback; or accepting a green check without mutation-proven rejection.

## 4. UI + interaction

`NO_UI_CHANGE`

2. They run `npm run api:contract:generate`, review only the OpenAPI/generated-TypeScript diff, then run `npm run api:contract:check` and normal gates.

## 5. Error handling

All failures exit non-zero, preserve the prior committed artifact set, and provide one stable category, one recovery, and safe repo-relative diagnostics. Unknown tool errors stay tooling failures; the implementation never guesses a source location or relabels a failed stage as drift.

| Category | Required first-line meaning | Recovery |
|---|---|---|
| `contract drift` | Completed byte comparison found differences; list changed repo-relative artifact paths. | `Run npm run api:contract:generate, review the diff, and commit the generated files.` |
| `missing output` | A required committed artifact path does not exist; name it. | Run the generate command. |
| `zero-operation output` | The artifact exists but contains no production operations. | Repair contract enumeration, then regenerate. |
| `unsupported schema construct` | A repository policy or stable tool diagnostic names an unsupported operation/construct and a vouched repo-relative location when available. | `Generation did not complete. Change the contract representation or the pinned generation chain, then rerun.` |
| `incomplete contract coverage` | A pre-cutover method/path pair is missing, an extra pair appears without reviewed baseline acceptance, or an inventoried operation/required response/security/header/media shape is absent. | Restore the preserved pair or complete the Rust contract registration/schema; an intentional endpoint change requires reviewed baseline acceptance before regeneration. |
| `invalid OpenAPI artifact` | Completed OpenAPI validation failed. | Correct the reported OpenAPI source definition, then regenerate. |
| `generation tooling failure` | Generation failed before comparison; name the stage and safe underlying diagnostic. | Repair the local installed tool/setup and rerun. Connectivity is mentioned only for dependency bootstrap when established. |
| `generated-client compilation failure` | Generated TypeScript or facade compilation failed; name the compiler repo-relative location. | Correct the contract/facade mismatch, regenerate if needed, and rerun. |

Only a completed byte comparison may use `stale` or `match`. Missing and zero-operation output are never collapsed. `unsupported schema construct`, `incomplete contract coverage`, and `invalid OpenAPI artifact` remain independently actionable.

## 7. Testing strategy

Automate silent and negative-space risks; review only intentional documentation and no-redesign evidence.

- **Rust unit/compile:** prove the pinned `OpenApiRouter`, concrete response-enum inference, operation identity uniqueness, canonical ordering/newline, schema policy, exact 52-operation inventory, and deterministic exporter. Poison registration, response set, identity, media/security coverage, and null/omitted shapes; prove red then restored green.
- **Generation/tool tests:** first capture the existing production router into the independent pre-cutover baseline, verifying its 52 sorted pairs and source/tool provenance. Then run generate/check in isolated roots, offline with dead proxies; compare hashes; interrupt before atomic replacement; remove/empty/corrupt artifacts; fail each stage; scan forbidden values/paths; mutate generated bytes, exception catalogs, every parity-coverage set, the TypeScript header, and every sentinel/manifest field. Prove valid structured JSON receives no prefix/extra field; wrong/missing/extra paths, hashes, kinds, media types, writers, constants, ordering, or unlisted non-text outputs fail; a failed install restores the prior mutable artifact set. The checker derives expected operation/boundary keys from OpenAPI, resolves both evidence modes to actual named cases/outcomes, enforces the nine-class and two-mode enums, and proves missing/extra/duplicate/unknown/mode-mismatched operation, boundary, evidence, outcome, runtime-only row, or normalizer failures with restored clean controls. Mutations also prove that an unexecuted fixture row and a direct request relabeled as a different operation or shared mapping family are rejected.
- **Independent-baseline anti-vacuity:** remove the same operation from a test copy of the post-migration runtime and OpenAPI graph, leave `precutover-operation-baseline.json` unchanged, and observe both generate/check reject the missing pair. Hash the baseline before/after ordinary commands to prove they cannot rewrite it. Reject capture on dynamic/unsupported router syntax, reject baseline acceptance without the exact review marker/pair diff/reason, and prove the reviewed accepting control atomically updates provenance.
- **TypeScript/library:** strictly compile `schema.ts`, the `openapi-fetch` client, facade, and consumers. AST checks reject duplicate migrated wire declarations and generated deep imports. Unit tests preserve named exports, error/null/coalescing/abort behavior, same-origin credentials, and malformed SSE event isolation.
- **Response-conversion integration:** execute the production-owned route/source registry without reading OpenAPI. For every independently persisted pre-cutover signature, construct a valid representative Axum response through its actual `IntoResponse`/extractor path and assert exact status, meaningful header set/value policy, media/no-body, body category/valid representative body, and security binding. Then independently derive the OpenAPI material boundary set (181 at this amendment) and require registry source IDs, signature IDs, evidence IDs, and emitted outcome IDs to be bijective with it. Mutations cover missing/extra/duplicate/drifted/comment-only/metadata-only entries. This suite proves envelopes, not exact DTO bytes.
- **Typed-schema integration:** mutate each boundary's route-owned Rust DTO/`IntoResponses` schema signature and prove the deterministic OpenAPI/generated-TypeScript graph changes or rejects drift; compile generated consumers. Direct HTTP high-risk scenarios assert actual body shapes so representative envelope bodies cannot masquerade as DTO parity.
- **Direct router/runtime integration:** use hermetic market/store/clock fixtures and send real requests through the production Tower/Axum router. Execute at least one distinct scenario for every source-derived operation, then the required positive/negative auth modes, cookie/mutating success and refusal effects, OAuth state/redirect/cookie matrix, operator/research success/denial/not-found/fault, SSE open/validation/drop/capacity/pre-stream JSON, operator/trader isolation, fallback/implicit methods, and representative shared `400`/`401`/`403`/`404`/`409`/`422`/`500`/`502`/`503` families. One direct fault case may cover a shared production mapping family, never a relabeled operation.
- **SSE integration:** through direct HTTP verify stream open, data-event meaning, validation, capacity and pre-stream JSON failures, and dropped stream; through the native adapter with generated types verify heartbeat/malformed isolation, close, reconnect, last-known behavior, and no duplicate subscription.
- **Domain regression:** existing score/tier/gate/fingerprint and quant fixtures stay byte-identical; `libs/quant-engine` remains free of HTTP/OpenAPI dependencies.
- **Application integration/review:** mock only the network boundary for dashboard integration tests; run affected page journeys and builds to prove import compatibility and absence of new routes/links/copy/states. Review README completeness/order flexibility and generated notice.
- **Live GATE Q:** run the `INTERFACE_CONTRACT.md` conformance block against the current server as a representative four-call JSON smoke check. It supplements—never substitutes for—`apps/api/openapi/precutover-operation-baseline.json`, the exhaustive response-envelope conversion evidence and typed-schema graph in `apps/api/openapi/parity-coverage.json`, the exact 52-operation inventory, or the risk-tiered direct HTTP transport/auth suite; `libs/api/README.md` and every gate summary emit the exact non-substitution warning next to the conformance guidance.

## 8. Guardrails this feature must not break

- **`production-fails-closed`:** stale, missing, partial, invalid, uncompilable, or unverifiable contract prerequisites stop normal build/release gates; generation never runs at startup and never falls back to old development behavior.
- **`structural-over-prose-enforcement`:** the independently captured immutable-by-default pre-cutover baseline, one post-migration runtime/OpenAPI graph, response-bound wire types, byte comparison, AST/import rules, set-equality catalogs, and mutation-proven red/green checks enforce the contract; deleting the same route from runtime and OpenAPI still fails against the baseline.
- **`cited-code-is-verified-not-assumed`:** existing route graph, TypeScript facade, EventSource lifecycle, auth/cookie behavior, and package scripts were read at source; the still-unproved concrete response-inference detail is a pre-migration stop condition, not an assertion.
- **`no-secrets-in-image`:** artifact generation uses no runtime values, the explicit negative scan covers new committed paths, production secrets stay runtime-injected, and images remain non-root.
- **`server-side-gate-enforcement`:** generated security declarations and facade behavior never replace direct server enforcement; bypassed client checks remain refused.
- **`absent-is-not-none`:** required-nullable, optional/omitted, empty, and closed unknown/inapplicable states remain distinct in Rust serialization, OpenAPI, generated TypeScript, facade behavior, and visible meaning.
- **`operator-vs-trader-path-separation`:** the artifact describes both surfaces without linking, invoking, recomputing, mutating, or exposing operator/research functions in trader flows; no runtime docs route is added.
- **`additive-keeps-score-byte-identical`:** gate, score, tier, fingerprint, entry eligibility, gamma sources, and all established quant calculations remain byte-identical; contract tooling does not enter `libs/quant-engine`.
