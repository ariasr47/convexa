## Critical  (blocks — must loop back to R4)

- None. Pass-1 Critical (put-then-insert under a **deterministic identity locator** → index first-wins, **body last-wins**, orphan story false) does not hold on the current text.

  Repair checked against the four claims:

  1. **Unique-per-put locator** — SPEC §2.2: “the storage key is **unique per put**, not derived from `(symbol, et_date)` alone.” §2.7: “Identity-only / `(symbol, et_date)`-deterministic body locator” is a rejected approach because it “last-win[s] the body bytes.” INTERFACE standing rule 13: “Identity-only shared keys are forbidden (would last-win the body).”
  2. **Put then `insert_if_absent`** — SPEC §2.2 Write path: existence check returns `Ok(false)` without body I/O; otherwise “**`put` body under a unique-per-put key**, then **`insert_if_absent` on the index** with that locator (`ON CONFLICT DO NOTHING` / in-memory check).” INTERFACE rule 13: “put then `insert_if_absent`.”
  3. **First body retained** — SPEC §2.2 step 3: “the **first body is retained** via the winning index row.” AC-9 **(SB)**: “the index first-wins row retains the **first** body.” Matches shipped first-wins: live Postgres is one atomic `INSERT … ON CONFLICT DO NOTHING` that binds `body` in the same statement — whichever insert commits first keeps its bytes (`pg_session_chain_archive.rs` lines 36–50). Unique keys make the index winner’s locator point at **that writer’s** blob, not a shared object the loser can overwrite.
  4. **Orphan is real** (for the different-body race the shipped invariant cares about) — two racers with different `source_as_of` (live `first_wins_second_insert_same_et_date_keeps_first_body` uses 14:00 vs 20:00) put distinct keys; loser insert is `DO NOTHING`; loser blob is not the winner’s object. SPEC §2.2 step 4: “Do **not** put under a key two racers share.”

  Live writers that made the race non-theoretical still exist: `capture.rs` `archive_session_best_effort` after append; `ensure.rs` the same helper on promote and direct archive. The spec now requires those concurrent `(symbol, et_date)` puts to leave exactly one identity with the first retained body.

  Residual: “include `source_as_of` (and/or a put nonce)” can still share a key when `source_as_of` matches — Important below, not a reopen of last-winning a **different** book. — evidence: SPEC.md §2.2 Body locator + Write path; SPEC.md §2.7 identity-only reject; SPEC.md AC-9; INTERFACE_CONTRACT.md standing rule 13; `apps/api/src/db/pg_session_chain_archive.rs` `INSERT INTO session_chain_archive … body` `ON CONFLICT (symbol, et_date) DO NOTHING`.

## Important  (should fix)

- **“Unique per put” is not implied by `source_as_of` (and/or a nonce).** SPEC §2.2: “Include `source_as_of` (and/or a put nonce) so two concurrent writers for the same identity **never share a key**.” INTERFACE opener: “unique per put (include `source_as_of` and/or a nonce — never identity-only).” `source_as_of`-only is unique per **(identity, as_of)**, not per **put**. Live same-as_of race: `capture_into` archives the ring wire after append (`capture.rs` `archive_session_best_effort(archive, &wire, &bytes)`); `ensure.rs` `try_promote` loads the first same-day ring snapshot and archives **that same** `wire.as_of`. Liquid-name ensure vs `spawn_capture` for SPY on one ET date can therefore `put` the same key, second `put` overwrites the winner’s object, and AC-9’s “losing put is an orphan blob (not an overwrite of the winner’s object)” is false. Different-as_of first-wins (the shipped 14:00 vs 20:00 body) still holds — that is why this is not the prior Critical. Bind a put nonce (or any token unique per `put` call). Do not leave PLAN the “or” that omits it. — evidence: SPEC.md §2.2 “and/or a put nonce”; SPEC.md AC-9 “not an overwrite of the winner’s object”; INTERFACE_CONTRACT.md “source_as_of and/or a nonce”; `apps/api/src/services/chain_snapshot/capture.rs` post-append archive; `apps/api/src/services/session_chain_archive/ensure.rs` `try_promote` / `try_promote_bytes`.

Migrator scheduling remains “one-shot (or boot-idempotent)” — a lazy first-request backfill would await FS put on `load` / `insert_if_absent` and fail AC-13/14. — evidence: SPEC.md §2.4; SPEC.md §2.7 pointer theater; SPEC.md AC-1/2, AC-13/14; `apps/api/src/db/migrations.rs` v11 `body BYTEA NOT NULL`; `pg_session_chain_archive.rs` INSERT column list.
