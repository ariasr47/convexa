## 1. Goal + scope

Give Convexa maintainers and reviewers one honest, repeatable browser-quality gate that retains the full existing Chromium Playwright suite, adds bounded compatibility, automated accessibility, and visual-regression checks, and reports actionable local/CI evidence. Product behavior remains unchanged except for the narrow, independently reproduced accessibility repairs authorized by owner rulings D7 and D8: the D7 ticker-grip, named contrast, Settings-label, skip-focus, and honest cold-error outcomes, plus one coherent Scanner-card link tab stop, the additional named Ticker/Positions contrast and sparkline-semantics corrections, auth-dialog opener focus restoration, and visual-viewport reachability for three existing Positions controls at proven Chromium page scale 2. The tested-browser promise is limited to the Chromium, Firefox, and WebKit engines installed by the repository's locked Playwright release because those are the engines this feature can actually execute; Browserslist, if retained as emitted-code intent, is not behavioral evidence for branded browsers. Reports name the actual Playwright version, project, and engine and do not claim coverage for every Chrome, Edge, Firefox, Safari, iOS Safari, operating-system, real-device, extension, embedded-webview, or assistive-technology combination. A Playwright lockfile upgrade is the explicit engine-version refresh and compatibility/baseline review event.

**In scope:**

- Preserve the observed pre-feature inventory of 52 tests in five files under the full Chromium `dashboard-e2e:e2e` target, guarded by checked set equality.
- Run exactly five named compatibility journeys in each pinned Chromium, Firefox, and WebKit project, separate from the full-suite selection.
- Run exactly nine state-specific Chromium axe scans, block `serious` and `critical` findings, and retain `moderate` and `minor` findings in summaries and artifacts.
- Compare exactly six deterministic, platform-scoped Chromium screenshot baselines.
- Expose explicit Nx and root npm targets for Chromium, compatibility, accessibility, visual comparison, deliberate visual candidate generation, and the aggregate quality gate.
- Add deterministic test-only fixtures, strict request interception, state-specific readiness, non-vacuity guards, machine-readable summaries, per-gate artifacts, and compare-only hosted workflow wiring.
- Report hosted browser quality as `NOT RUN` while hosted-runner evidence is unavailable; local results remain local evidence.
- Add only development/e2e dependencies and repository/CI test tooling, plus the D7/D8 product-source allowlist and observable outcomes in §2–§4. `NO_BACKEND_CHANGE` remains binding; product changes outside that allowlist are prohibited.

**Out of scope:**

- Any layout redesign, new component or feature, route change, public-asset change, theme-token or global-palette change, motion change, unrelated copy/style/semantic cleanup, runtime dependency, API/backend/quant change, scoring/fingerprinting change, durable-data change, or real account/market/vendor use. D7 and D8 permit only the named semantic, local contrast, label, focus-handoff, coherent-link-tab-stop, and visual-viewport reachability corrections inside the already closed matrix; they do not authorize a broader accessibility sweep or opportunistic cleanup.
- Multiplying all 52 existing tests across Firefox and WebKit, or running visual comparison across three rasterizers.
- Branded-browser certification, beta/nightly or legacy coverage, a device lab, performance budgets, live-market correctness, or assistive-technology certification.
- A complete/manual WCAG audit; automated axe output is only a serious/critical regression gate for the named states.
- Broad axe exclusions, silent grandfathering of product violations, broad screenshot masks, guessed visual tolerances, automatic baseline acceptance, baseline writing from a check or CI path, or a hosted visual service.
- Claiming hosted success, required-check evidence, artifact-upload success, or Linux baseline stability before a real hosted run produces it.

**Future (deliberately deferred):**

- Real stable Chrome, Edge, Firefox, Safari, iOS, device, and assistive-technology coverage based on observed user share and support cost.
- Ticker loading/stale scans, auth-dialog scans, Scanner worker-down scans, Settings validation scans, and broader manual keyboard/screen-reader/zoom/cognitive audits beyond the closed nine-scan inventory.
- Additional screenshot compositions only after a separately approved scope change demonstrates a material risk missed by the closed six-image set.
- A recorded hosted pass and merge-required status after hosted runners/billing return and the Linux baseline set has been deliberately reviewed.

## 2. Architecture

The feature stays inside the existing `apps/dashboard-e2e` Playwright boundary plus repository command/CI wiring. The live seams at synthesis are Playwright `^1.62.1`, Nx `23.1.1`, an inferred `dashboard-e2e:e2e` target, one Chromium project in `apps/dashboard-e2e/playwright.config.ts`, five existing specs under `apps/dashboard-e2e/src/e2e/`, a port-4200 Playwright web server, CI-only retry count 1, and a hosted workflow that currently installs Chromium and invokes the e2e target. These are observed attachment points, not proof that any browser run passed during synthesis.

Create one checked quality manifest under `apps/dashboard-e2e/src/quality/` as the selection authority. It records: the 52 pre-feature full-Chromium test identities; the five compatibility journey IDs and their three engine arms; the nine accessibility surface/state identities; the six visual scenario dimensions; expected per-gate artifact roots; and the engine-scoped support policy. Set-equality guards reject missing, duplicate, zero, or surplus inventory. Compatibility-only specs live outside the full-suite selection, so the aggregate runs the retained 52-test Chromium suite once and the five Chromium compatibility arms once, rather than recollecting either group.

The same quality area owns a strict fixture harness, state readiness/vacuity assertions, run-summary/reporting helpers, accessibility waiver validation, and compatibility/accessibility/visual specs. Each scenario record declares route, auth state, disposable durable-browser seed, fixed network profile, stream state, fixed clock/time zone/locale, viewport, color scheme, and ready/error anchor. Every `/api` and SSE request a new quality scenario can issue is fulfilled deterministically or rejected as unexpected; no request falls through to a live backend, vendor, account, market clock, or internet service. Each test gets a fresh browser context, and fixture setup never migrates, deletes, or promotes real user storage.

D7 adds a separate, presentation-only product repair boundary. It may touch only `apps/dashboard/src/app/shared/ui/Widget/Widget.tsx` for the non-interactive ticker grip; `apps/dashboard/src/app/pages/ticker/TickerDashboard.tsx` and the existing empty/context renderers under `dealer-flow-projection/DealerFlowProjection.tsx`, `market-context/MarketContext.tsx`, `iv-rank/IvRank.tsx`, `straddle-move/StraddleMove.tsx`, and `term-structure/TermStructure.tsx` for the independently observed contrast targets; `apps/dashboard/src/app/features/auth/SettingsPage.tsx` for the existing Settings ticker input's accessible name; and `apps/dashboard/src/app/shell/AppShell.tsx` for the existing skip link's focus handoff. These changes may use existing theme slots and existing visible copy only; they may not change layout, data flow, state ownership, routes, persistence, API calls, global tokens, or feature behavior. The cold-error product path remains the existing `getTicker` → `usePollingResource` → Ticker `role="alert"` path; the test fixture selects HTTP 503 so the observable shipped message is `API error 503`.

D8 expands that product boundary only through exact selector-tied source families: `apps/dashboard/src/app/pages/scanner/ScanCard.tsx` and `ScanCells.tsx` for `[data-testid="scan-card"]` and its nested `[data-testid="cell-score"]`; `apps/dashboard/src/app/pages/ticker/widgets/fresh-positioning/FreshPositioning.tsx`, `off-exchange-blocks/OffExchangeBlocks.tsx`, and `chrome/TapePulseStrip.tsx` for the named A11Y-3/A11Y-9 empty and stream-state text; `apps/dashboard/src/app/features/trading/positions/PositionRow.tsx` and `PlSparkline.tsx` for the `[data-testid="trend-sparkline"]` Tooltip wrapper; `CustomizationToolbar.tsx`, `PortfolioPanel.tsx`, `PositionCard.tsx`, and `LegDisclosure.tsx` for the named A11Y-5 contrast targets and the existing `open-entry`, `tab-live`, and `leg-disclosure-toggle` controls; `apps/dashboard/src/app/features/trading/positions/PositionsPanel.tsx` for `[data-testid="positions-disclosure"]`; `apps/dashboard/src/app/features/trading/outcomes/TrackRecordSection.tsx` for `[data-testid^="tr-family-empty-"]`; and `apps/dashboard/src/app/features/auth/RequireAuth.tsx`, `AuthDialogProvider.tsx`, and `AuthDialog.tsx` for `[data-testid="require-auth-signin"]` opener restoration. The exact co-located evidence files `apps/dashboard/src/app/features/trading/positions/positions.risk.spec.tsx` and `apps/dashboard/src/app/features/trading/outcomes/track-record.flow.spec.tsx`, other co-located component tests for the already listed owners, and the existing browser-quality specs may change only to prove those outcomes. No other dashboard source family is authorized by D8, and no authorized file may be used for redesign, a new journey or scan, an axe waiver or threshold reduction, unrelated cleanup, or backend/API behavior.

AC45 may use one bounded, visual-viewport-aware focus-scroll seam inside the already authorized `open-entry`, `tab-live`, and `leg-disclosure-toggle` owners. The seam activates only when a focused named control does not intersect the current `visualViewport` and computes against that viewport's offset and dimensions; ordinary `scrollIntoView` against the 900px layout viewport is insufficient when the proven scale-2 visual viewport is 640×450. This is focus accommodation, not layout: it cannot resize, reorder, restyle, or reparent a control, add a mode, mutate state, run for unrelated elements, substitute CSS zoom, or change the independent 393×852 composition. The browser oracle still must prove scale 2 before the seam and intersection afterward.

Tooling repairs remain isolated under `apps/dashboard-e2e` and are not product fixes: the Scanner SSE fixture must emit the application-consumed event shape; the deterministic book fixture must not overwrite its seeded positions; anonymous scenarios must use one consistent anonymous session; the watchdog arm must advance and observe the full 15-second boundary; and the zoom/reflow oracle must run in an isolated environment that first proves its requested scale rather than relying on an invalid CSS-zoom substitute. A tooling defect cannot be hidden by changing product code, and a D7 product repair cannot weaken fixture strictness, readiness, or the closed matrices.

Visual capture uses Playwright-native `toHaveScreenshot` in Chromium only. Snapshot identity is the closed tuple of scenario, viewport, scheme, application state, Chromium project, Playwright/browser revision, and host platform. Capture waits for the named application anchor and `document.fonts.ready`, fixes locale/time zone/clock/device scale, selects reduced motion, hides the caret, disables capture-time animation, and fixture-fixes volatile values. It does not use `networkidle` because the app has SSE. Check mode sets snapshot updates to `none`; update mode is a distinct uncached, non-parallel path that can write only current-platform candidates from the six-case manifest. Any proposed mask names the exact out-of-scope field; broad masks are rejected. Pixel tolerance begins at zero and may change only through a separately reviewed, repeat-measured amendment.

`apps/dashboard-e2e/project.json` gains explicit `e2e`, `compat`, `a11y`, `visual`, `visual-update`, and `quality` targets. `quality` is an uncached `nx:run-commands` target whose sole command is `node apps/dashboard-e2e/tools/run-quality.mjs`; it has no `dependsOn`. The four check targets and visual update are also uncached; visual update is serialized. The root `package.json` exposes the matching commands in §4. All child gates therefore execute against current browser/runtime bytes rather than relying on restored Nx success.

`dashboard-e2e:quality` invokes the cross-platform Node entry `apps/dashboard-e2e/tools/run-quality.mjs`; it does not rely on Nx task-bail semantics. The runner freezes the exact child set to `dashboard-e2e:e2e`, `dashboard-e2e:compat`, `dashboard-e2e:a11y`, and `dashboard-e2e:visual`, rejects any duplicate or fifth child before launch, and spawns each exactly once as executable `npx.cmd` on Windows or `npx` elsewhere with argument vector `["nx", "run", target, "--skip-nx-cache"]`, `shell: false`, inherited stdio, and environment `NX_DAEMON=false`, `BROWSER_QUALITY_RUN_ID={run_id}`, `BROWSER_QUALITY_SOURCE_REVISION={40-hex revision}`. It constructs all four spawn promises before awaiting `Promise.allSettled`, waits for every child close/error event, then validates every child summary at the exact roots below. A spawn rejection, non-zero exit, missing/invalid summary, duplicate execution key, zero selected/executed count, source-revision mismatch, or artifact-hash mismatch makes the aggregate non-zero after all siblings settle. `visual-update` is not a runner constant, accepted CLI argument, Nx dependency, or reachable subprocess.

The runner writes `apps/dashboard-e2e/test-output/playwright/quality/summary.json` with this exact aggregate identity: `schema_version: 1`; `gate: "quality"`; `run_id`; `source_revision`; `started_at`; `completed_at`; `status: "pass"|"fail"|"incomplete"`; and exactly four `children[]` records containing `target`, `execution_key`, `invocation_count: 1`, `exit_code`, `summary_path`, `summary_sha256`, and `status`. `execution_key` is `{run_id}:{target}`. The file is written only after all four promises settle; an incomplete record is a failure receipt, never a pass.

Each child writes one stable machine-readable summary at exactly `chromium/summary.json`, `compatibility/summary.json`, `accessibility/summary.json`, or `visual/summary.json` below `apps/dashboard-e2e/test-output/playwright/`. Common fields are `schema_version`, `gate`, `run_id`, `source_revision`, `selected`, `executed`, `passed`, `failed`, `flaky`, `not_run`, `status`, `playwright_version`, `browser_revision`, `host_platform`, and resolved `artifacts[]` entries with `path` and `sha256`. Compatibility adds engine/journey identities, accessibility adds surface/state/axe-finding identities, and visual adds scenario/platform/baseline identities.

The full-Chromium summary at `apps/dashboard-e2e/test-output/playwright/chromium/summary.json` has an explicit identity schema rather than relying on artifact paths: `gate: "chromium"`; `inventory_id: "pre-feature-52-v1"`; `project: "chromium"`; the common fields above; and exactly 52 unique `tests[]` records containing `test_id`, repository-relative `file`, ordered `title_path[]`, `project: "chromium"`, `status: "passed"|"failed"|"flaky"|"not_run"`, `retries`, and `artifact_paths[]`. The ordered `test_id` set must equal the checked manifest and `selected = tests.length = 52`; missing, duplicate, surplus, or path-inferred identities fail.

One execution-unit key is allowed per scheduled child/engine/state/scenario; duplicates, missing summaries, incomplete artifacts, zero selection, or configured-but-not-executed units make the aggregate fail. Compatibility failures retain engine/journey traces and screenshots; accessibility artifacts retain route/state, rule ID, impact, help URL, and target selector; visual failures retain expected, actual, and diff images.

Human visual authority is durable and externally inspectable under `apps/dashboard-e2e/visual-review/`; the update command never creates an authorization or acceptance decision:

- Pre-generation authorization lives at `apps/dashboard-e2e/visual-review/authorizations/{authorization_id}.json` with exactly `schema_version: 1`, `authorization_id`, `decision: "authorize_candidate_generation"`, `state: "authorized"`, `actor: { "id": <non-empty>, "role": "owner"|"design_reviewer" }`, `source_revision`, `platform`, `created_at`, `failed_compare: { "run_id", "summary_path", "summary_sha256" }`, and six manifest-equal `scenarios[]` records containing `scenario_id`, `expected_path`, `expected_sha256|null`, `actual_path`, `actual_sha256`, `diff_path`, and `diff_sha256|null`.
- Candidate generation is invoked as `npm run browser:visual:update -- --authorization apps/dashboard-e2e/visual-review/authorizations/{authorization_id}.json`. It validates the receipt and evidence, writes only the authorized current-platform PNGs, and generates `apps/dashboard-e2e/visual-review/candidate-sets/{candidate_set_id}.json` with exactly `schema_version: 1`, `candidate_set_id`, `authorization_id`, `state: "candidates_written"`, `generated_by: { "actor_id", "command": "npm run browser:visual:update" }`, `source_revision`, `platform`, `manifest_sha256`, `generated_at`, and six `candidates[]` records containing `scenario_id`, repository-relative `path`, and `sha256`.
- Post-generation review lives at `apps/dashboard-e2e/visual-review/acceptances/{candidate_set_id}.json` with exactly `schema_version: 1`, `acceptance_id`, `candidate_set_id`, `decision: "accept_candidates"|"reject_candidates"`, `state: "accepted"|"rejected"`, `actor: { "id": <non-empty>, "role": "code_reviewer" }`, `source_revision`, `platform`, `reviewed_at`, `authorization_path`, `authorization_sha256`, `candidate_receipt_path`, `candidate_receipt_sha256`, `source_diff_path`, `source_diff_sha256`, and six manifest-equal `candidates[]` records containing `scenario_id`, `path`, and the reviewed `sha256`. `source_diff_path` is exactly `apps/dashboard-e2e/visual-review/diffs/{candidate_set_id}.patch`.

For all three receipt types, identifiers match `^[a-z0-9][a-z0-9._-]+$`; `source_revision` is the 40-hex Git commit rendered by the failed compare; SHA-256 fields are lowercase 64-hex; timestamps are RFC 3339 UTC; `platform` is `win32` or `linux`; and every path is repository-relative POSIX text with no absolute prefix or `..`. The authorization may be committed after `source_revision`, but validator-visible changes since that revision must then be limited to its own `visual-review/authorizations/` receipt; any product, fixture, manifest, config, or baseline change makes it stale. Required actual/candidate/receipt/source-diff hashes are never null; `expected_sha256` and `diff_sha256` may be null only for a manifest-declared missing-baseline failure.

The enforced state machine is `compare_failed → authorized → candidates_written → accepted|rejected → stability_clean`. Candidate generation requires the `authorized` receipt and exact source/platform/scenario/artifact hashes; acceptance requires a candidate-set receipt and exact current PNG/source-diff hashes; only `accepted` may proceed to two compare-only runs. Empty actor IDs, wrong roles, malformed timestamps, revision/platform mismatch, path escape, stale/reused authorization, missing/duplicate/surplus scenarios, missing/null required hashes, any hash mismatch, acceptance before candidate generation, command-generated authorization/acceptance, rejected candidates, changed PNGs after acceptance, or fewer than two clean no-retry comparisons all fail. The command can report only `candidates_written`; it has no transition to `accepted`.

Future Linux bootstrap is explicit. Once hosted runners return, a compare-only Ubuntu run at the target source revision must first fail on missing Linux baselines and upload its actual/missing-baseline evidence. An owner/design reviewer records the authorization receipt above. A separate manual-only `.github/workflows/browser-visual-linux-candidates.yml` (`workflow_dispatch` only, protected `visual-baseline-candidate` environment, read-only repository permissions, exact source revision and authorization path inputs) may then run only the visual-update command on Ubuntu and upload the six candidate PNGs plus candidate-set receipt; it has no push/pull-request trigger, no aggregate/check status, and no commit permission. A maintainer downloads those exact hashed files into the platform-scoped snapshot paths, normal code review records the acceptance receipt and accepts/rejects the PNG/source diff, and the accepted baseline commit must produce two independent compare-only Ubuntu passes at the same revision/platform with zero retry and unchanged hashes before hosted visual evidence can become PASS. Merge CI and every check path remain compare-only and structurally unable to update.

The hosted workflow installs all three locked Playwright engines, invokes `npm run browser:quality` exactly once, and never invokes a constituent target directly. Separately named `always` publication steps only read/upload each child artifact root; they do not run Playwright or Nx. Missing expected evidence makes publication non-zero. Workflow wiring is inspectable now, but hosted runtime status remains `NOT RUN` until a real hosted execution exists.

Expected touched/created seams are `package.json`, `package-lock.json`, `apps/dashboard-e2e/project.json`, `apps/dashboard-e2e/playwright.config.ts` and quality-specific Playwright configuration/helpers under `apps/dashboard-e2e/`, `apps/dashboard-e2e/tools/run-quality.mjs`, new specs/fixtures/manifest/reporting modules under `apps/dashboard-e2e/src/quality/`, `apps/dashboard-e2e/visual-review/` receipts, platform-scoped snapshots owned by those visual specs, `.github/workflows/ci.yml`, the manual-only `.github/workflows/browser-visual-linux-candidates.yml`, and only the D7/D8 product files explicitly allowlisted above. No other file under `apps/dashboard/src/` may change; no file under `apps/dashboard/public/`, `libs/api/`, `apps/api/`, or `libs/quant-engine/` may change.

**Failure modes + isolation:** A child failure does not stop siblings from producing evidence and never overwrites a sibling artifact root; the aggregate fails after collecting all available summaries. A missing engine, unavailable app server, zero selection, fixture/readiness failure, unexpected request, expired/invalid waiver, missing baseline, changed pixel, flaky-after-retry test, duplicate execution, or incomplete artifact is non-zero and cannot be recorded as a pass. A configured but unexecuted hosted arm remains `not run`. Test fixtures and evidence are synthetic, fresh-context, and test-only, so failures cannot mutate production data or product runtime.

**Not buildable / rejected approaches:** Do not fan the full suite across all engines, use one smoke test per engine, add Storybook/Percy/Chromatic or another renderer/review authority, compare Windows PNGs to Linux PNGs, let checks create missing snapshots, use `networkidle` as readiness, fall through to live services, infer support for vendor browsers from Browserslist/engine proxies, hide real findings behind exclusions, or let CI/check targets reach update mode. These approaches either overclaim evidence, multiply cost/noise, introduce a second authority, or create vacuous green results.

## 5. Error handling

- **Prerequisite:** A missing Chromium/Firefox/WebKit install or unavailable port-4200 dashboard exits non-zero with the exact BLOCKED copy in §4 and records no browser pass. Local recovery is `npx playwright install chromium firefox webkit`; CI may use `--with-deps`.
- **Selection/readiness:** Zero, missing, duplicate, surplus, skipped, blank, wrong-state, or configured-but-unexecuted units exit non-zero. SSE means `networkidle` is never accepted as readiness; failure to reach the scenario anchor is a fixture/readiness failure.
- **Fixture isolation:** Unexpected `/api`/SSE traffic is aborted and reported. A strict fixture failure cannot fall back to a real backend, account, vendor, wall clock, or stale fixture and cannot be relabeled an application empty state.
- **Compatibility:** The result names the tested engine and journey only. Independent arms continue so each can retain evidence; the aggregate remains non-zero.
- **Accessibility:** Every real in-scope serious/critical product finding fails and enters GATE Z. A waiver is valid only for an independently proven axe false positive or third-party node outside Convexa control and only when exact rule, selector, evidence/rationale, owner, removal condition, and future expiry all match. Broad, unowned, non-matching, or expired waivers fail. There is no retry that turns a product finding green.
- **D7 product findings:** The named grip, contrast, Settings-label, and skip-focus defects are release-blocking until AC29–32 pass against the actual rendered nodes. The cold-error arm fails unless the existing 503 path renders `API error 503` plus `Retry` and contains no fixture wording. A failure outside this exact repair set re-enters GATE Z; it is not permission for adjacent cleanup.
- **D8 product findings:** The scanner nested tab stop, Fresh positioning/Off-exchange/tape contrast, position sparkline semantics, named Positions contrast, dialog opener restoration, and real-scale visual-viewport failures are release-blocking until AC40–45 pass against the actual rendered nodes. They cannot be waived, threshold-lowered, or broadened into a redesign or unrelated cleanup; any newly discovered product finding re-enters GATE Z.
- **D7 tooling findings:** Scanner SSE shape, seeded-book overwrite, anonymous-session mismatch, watchdog timing, and zoom-arm isolation fail at the e2e fixture/oracle boundary. They cannot be waived, relabeled as product failures, or repaired by changing application behavior.
- **Visual:** Missing or mismatched baselines fail check mode without writing expected images. Artifact output retains expected/actual/diff when Playwright can produce them. Failure to create complete evidence is separately non-zero; it is not treated as “no difference.” Update without a schema-valid, hash-valid `authorized` receipt writes nothing; an update can emit only a `candidates_written` receipt. Missing/rejected/stale/mismatched acceptance or fewer than two clean comparisons blocks merge. Linux baseline absence follows the manual bootstrap in §2 and can never cause a PR/push/check run to update.
- **Flake:** CI may retain one Playwright retry for diagnostic artifacts, but Playwright 1.62.1's fail-on-flaky behavior makes any retry-only pass non-zero and prints the exact flaky copy. Gates do not automatically rerun until green.
- **Aggregate/evidence:** `run-quality.mjs` launches the frozen four-child set exactly once with `shell:false`, awaits all children through `Promise.allSettled`, and writes the aggregate receipt only after settlement. A child failure does not stop independent siblings. Spawn rejection, non-zero exit, missing/schema-invalid child summaries, duplicate execution keys, wrong source revision, zero counts, incomplete artifacts, or publication gaps fail the aggregate/publication path. No child is replayed to reconstruct missing evidence.
- **Hosted:** Workflow configuration is not execution evidence. Until a real hosted run exists, the state remains the exact `NOT RUN` line from §4.

## 7. Testing strategy

Automation is risk-based and concentrated on rules that can silently regress. Structural/unit tests mutation-probe manifest set equality, non-vacuous counts, selection separation, the frozen `run-quality.mjs` child array, `shell:false`, all-settled completion, exactly-once execution keys, child-summary validation, aggregate/update unreachability, strict unexpected-request failure, retry-only failure, artifact completeness, hosted command topology, and every axe-waiver field/expiry. The full-Chromium summary is checked against the exact 52-record schema. Each A11Y readiness row is proven non-vacuous by poisoning one required positive predicate and one forbidden-state predicate; each A11Y-B sequence is executed with the named route/order/oracle. The axe negative control injects a known serious violation and proves the gate rejects it; a moderate/minor control proves the finding remains visible without alone crossing the threshold.

Visual negative controls prove missing baselines and changed pixels fail without writes. Authorization/acceptance validators are mutation-tested for every required field, actor role, state transition, source/platform/scenario set, path boundary, source-diff/artifact/PNG hash, receipt reuse, and receipt order. A subprocess stub proves the update command cannot create or edit authorization/acceptance receipts. Repeated compare-only runs prove stability on one platform. The manual Linux workflow is structurally tested to allow only `workflow_dispatch`, require the protected environment and read-only repository permissions, invoke only the authorized update command, upload without commit, and remain unreachable from push/pull-request/aggregate/check graphs. Compatibility breaks are injected per engine/journey to prove isolation and actionable artifacts.

Playwright integration tests exercise only the browser/network boundary: application REST, SSE, auth, durable state, time, and market data are deterministic fixtures; production modules are rendered unchanged except for the D7/D8 allowlisted presentation/semantic/focus repairs. The full pre-feature Chromium inventory remains a distinct tier. Compatibility is a five-journey × three-engine tier, accessibility is a nine-scan Chromium tier plus explicit behavioral assertions, and visual is a six-scenario Chromium/platform tier. Review covers policy wording, exact operator/product copy, two-stage image authority, and design-canon adherence; these are not converted into brittle DOM/source assertions merely to call them automated.

D7 verification keeps two failure domains explicit. Product-oracle tests cover the exact grip selector, named contrast targets, actual Settings input accessible name, route-preserving skip focus, and the status-derived cold alert. Separate fixture tests mutation-probe the Scanner SSE envelope, seeded-book preservation, anonymous-session identity, the 15-second watchdog boundary, and a genuinely proven isolated browser-scale arm. Removing either side's repair must fail its own oracle without changing the other side or reducing the 52/5/9/7/6 inventories.

D8 adds focused component regressions for the Scanner card/score focus model, position sparkline Tooltip wrapper, named contrast nodes, auth-dialog opener lifecycle, and the three Positions focus-scroll seams. Focused Chromium browser evidence then exercises AC40–45 inside the existing A11Y-3/5/6/9, compatibility-3, and A11Y-B3/B5/B7 arms. Every focused test must fail when its exact repair is removed and pass after restoration; no new journey, scan, image, waiver, severity threshold, or visual tolerance is introduced.

GATE Q must observe commands and artifacts, not infer success from source. It verifies both accepting and rejecting sides, reads complete current-byte outputs, confirms that product changes are confined to the D7/D8 allowlist and outcomes, confirms no runtime/API/backend diff, and records hosted execution as `UNVERIFIABLE`/`NOT RUN` while runners are unavailable. A static CI-topology check can pass without becoming a hosted browser receipt.

## 8. Guardrails this feature must not break

- **`[structural-over-prose-enforcement]`:** Checked closed manifests, poison/mutation tests, strict fixtures, update-unreachable graph checks, and non-vacuous receipts make every load-bearing rule build-breaking.
- **`[theme-token-discipline]`:** Product theme/token files do not change. D7/D8 contrast repairs use existing local theme slots without hardcoded colors or a global palette shift. Dark/light tests consume the shipped theme; baselines never become a second token authority.
- **`[single-motion-moment]`:** No product keyframe or motion behavior changes. Reduced motion and capture-time animation suppression are test-harness controls only; existing motion inventory enforcement remains authoritative.
- **`[absent-is-not-none]`:** configured, selected, executed, skipped, not-run, missing-artifact, pass, fail, blocked, and candidate-written remain distinct evidence states. None collapses to PASS.
- **`[live-vs-static-isolation]`:** the Ticker stream-loss journey begins from a successful static bundle, degrades only live-derived UI, and proves static content remains; it cannot pass through a blank/error substitute.
- **`[loss-free-durable-migration]`:** no production durable key/shape changes. Fresh-context fixture seeds are disposable copies and never delete, migrate, or promote real browser storage.
- **`[operator-vs-trader-path-separation]`:** reports live only as test-run artifacts under the e2e output seam. No route, nav item, vendor call, recompute, cache mutation, or trader-path request is added.
- **`[cited-code-is-verified-not-assumed]`:** implementation attaches only to the inspected live package, Nx, Playwright, spec, workflow, and source-vouched selector seams named in §2/§4. Aggregate sibling completion comes from the specified Node `spawn`/`Promise.allSettled` mechanism, not assumed Nx task-bail behavior; selector/predicate drift is a visible contract failure.
- The full suite remains Chromium-only; the five/three compatibility matrix, nine scans, and six images are closed and cannot grow silently.
- `NO_BACKEND_CHANGE`, the D7/D8-limited UI boundary, score/tier/fingerprint identity, API behavior, runtime dependencies, public assets, and design canon remain intact. No repair changes feature behavior, data/state flow, route/history semantics beyond preventing the skip-link fragment mutation, or copy outside the exact cold-error oracle; D8 positioning changes are limited to focus-scroll reachability at real page scale 2 and preserve the separate 393px composition.
