# browser-quality-gates — brief
Goal:            Turn browser compatibility, accessibility, and visual stability into explicit local and CI quality gates: declare the supported browser policy; retain the full existing Chromium Playwright suite; add a bounded Firefox/WebKit journey matrix; add automated WCAG-oriented accessibility checks over representative public, authenticated, dense, and degraded states; add deterministic screenshot baselines for a small set of high-risk responsive/theme states; and expose clear Nx/npm targets for checking versus deliberately updating baselines. Preserve application runtime behavior, API behavior, scoring, motion design, and trader-visible UI.
Decision impact: N/A — frontend delivery correctness. Success is observed when a real browser-engine incompatibility, serious/critical accessibility regression, or approved visual baseline drift fails a named local command with actionable artifacts, while identical reruns remain byte/stability-clean and the existing full Chromium suite does not multiply blindly across every engine.
Feasibility:     pass — code-grounded 2026-08-23: `apps/dashboard-e2e` already uses Playwright 1.62.1 through Nx and runs 52 Chromium tests across five routes, responsive bands, both color schemes, authenticated states, and dense fixtures; its config explicitly records Firefox/WebKit as the deferred follow-on. No first-party Browserslist policy, axe Playwright integration, or Playwright screenshot baseline exists. The council must lock the supported browser promise, which journeys run on all engines, the accessibility severity/scope boundary, deterministic visual-fixture rules, baseline review/update authority, and what remains locally verifiable while GitHub-hosted runners are unavailable.
