# openapi-router-dependency-replacement — interface contract

**Status:** draft
**Backend impact:** internal route/OpenAPI integration replacement; `NO_WIRE_BEHAVIOR_CHANGE`
**Frontend impact:** `NO_UI_CHANGE`

This file is the FE↔BE truth for the maintenance replacement. The feature changes how the existing Axum runtime graph and OpenAPI document are assembled, but it changes no method, path, operation identity, request/response/error/event shape, status, meaningful header, media type, security mode, cookie effect, redirect, SSE behavior, or public `@convexa/api` semantic. No application or public documentation endpoint is added.

## Interface authority

The authoritative operation set is derived—not rewritten here—from the existing production registrations and must remain set-equal across:

- `apps/api/openapi/router-integration-prechange-baseline.json`, the one-time accepted pre-edit compatibility oracle;
- `apps/api/openapi/precutover-operation-baseline.json`, the immutable approved 52-operation method/path baseline;
- the Axum half of the one repository-owned `ContractRouter` production graph;
- `apps/api/openapi/convexa.openapi.json`, whose exact approved bytes remain the migration oracle; and
- `apps/api/openapi/parity-coverage.json`, which continues to derive 52 source-derived production operations, 181 material response conversions, and 87 direct-HTTP outcomes.

The archived `.spire/clusters/tech/contracts/_archive/api-contract-generation/INTERFACE_CONTRACT.md` records the approved pre-replacement endpoint inventory and access classifications. It remains historical evidence and is not edited. This contract deliberately does not copy that 52-row table: a second authored operation list would weaken the one-graph and immutable-baseline guarantees.

## Immutable pre-edit baseline

Before any replacement edit, the API contract owner creates `apps/api/openapi/router-integration-prechange-baseline.json` through repository-owned `tools/api-router-integration-baseline.mjs`: `npm run api:router-integration:baseline:candidate -- --source-revision <full-40-hex-sha> --out <temporary-path>` followed by `npm run api:router-integration:baseline:accept -- --candidate <temporary-path> --review-contract .spire/clusters/tech/contracts/openapi-router-dependency-replacement/INTERFACE_CONTRACT.md --reviewer-provenance <review-record>`. Candidate capture is non-writing; the accept path is the sole writer, refuses overwrite, and requires a clean passing contract graph whose pinned inputs are byte-equal to the recorded committed source revision. Ordinary generate, check, build, CI, and release commands have read-only access and must never create, rewrite, normalize, or accept this file.

Acceptance is a distinct reviewed repository checkpoint: the baseline is committed before any route, dependency, exporter, generated-artifact, or evidence-fixture replacement edit. Candidate comparison and normal check locate the commit that first added the baseline, require the recorded source revision to be its pre-edit parent for every pinned input, compare current baseline bytes with the first-added blob, and reconstruct the source artifact hashes/metadata/declared IDs through `git show <source.revision>:<repo-relative-path>`. A same-commit reorder, later baseline edit/deletion, substituted source revision, or shallow checkout unable to resolve the checkpoint blocks. This repository-history anchor makes baseline mutation detectable without placing the baseline in the generated manifest whose own bytes it pins.

These package-specific values are historical compatibility bytes inherited from the approved artifact. They do not name the current repository-owned implementation, must not be copied into active contributor/product documentation, and are not a license or security assertion by this feature. The whole OpenAPI raw hash and an independent exact object comparison both pin them so a count-preserving or canonicalization-hidden metadata change cannot pass.

For each evidence mode, the candidate tool independently obtains one ID set from the committed pre-edit `parity-coverage.json` and one from actual test execution: `CONTRACT_EVIDENCE_OUTCOME` lines for response conversions and `DIRECT_HTTP_EVIDENCE_OUTCOME` lines for direct HTTP. It rejects duplicates and requires declared and emitted sets to be equal before capture. The canonical set hash is SHA-256 over UTF-8 bytes of `JSON.stringify(sorted_unique_ids) + "\n"`, where sorting uses ascending Unicode code-point order and the JSON array contains the complete IDs without normalization or relabeling. The accepted baseline stores the count and resulting hash, not a second hand-authored case catalog.

Acceptance is blocked unless the existing canonical contract check, manifest self-validation, immutable 52-operation comparison, all 181 response-conversion executions, and all 87 direct-HTTP executions pass from source-revision-matched bytes. A missing/stale artifact, dirty pinned input, skipped runner, declared/emitted mismatch, or failing pre-existing gate cannot be blessed into the baseline.

After acceptance, `npm run api:router-integration:candidate` and `npm run api:contract:check` independently regenerate to separate temporary roots and each recomputes all four raw hashes, exact OpenAPI version/object equality, parity-declared ID sets, and execution-emitted ID sets against the baseline. Neither consumes the other's result or a cached pass receipt. Missing, extra, duplicate, relabeled, co-omitted, count-preserving substituted IDs; any artifact/metadata/hash drift; any baseline mutation/deletion; or any ordinary-command write attempt fails non-zero. The baseline itself is not added to `generated-artifacts.manifest.json`, whose pre-edit raw bytes are pinned; replacing this oracle requires a GATE-Z behavior-change contract.

## Registration boundary

Each production registration is one repository-owned package pairing an Axum handler path with its matching pinned-`utoipa` generated `__path_*` metadata type. One consuming `ContractRouter::route` call installs the handler's Axum method router at the metadata-derived path and merges that same package's operation, tags, and referenced schemas into OpenAPI. Runtime and document parts are obtained only by consuming `split_for_parts` on the completed graph; no partial or fallback graph is valid.

The route-owned Serde DTOs, response enums, `#[utoipa::path]` metadata, explicit schema-root registration, security application, and all existing post-processing remain authoritative and unchanged. The repository-owned constructor reproduces the exact approved OpenAPI 3.1 bootstrap metadata pinned above so canonical OpenAPI, generated TypeScript, parity, and manifest bytes do not drift.

## Preserved behavior

- All existing 52 source-derived production operations retain their public, optional-session, session, OAuth-state, operator-token, operator/research, or currently unconsumed access classification. The inventory is not a public-operation list.
- Authentication and authorization remain server-enforced. Anonymous, authenticated, forbidden, non-enumerating, operator-token, and not-found outcomes retain their distinct statuses, bodies, and absence of unauthorized mutation.
- Signup, login, logout, settings, OAuth, AI-key, broker, and other cookie-bearing flows retain existing `Set-Cookie`, clearing, security-attribute, browser-owned transport, redirect, and side-effect behavior. `POST /api/auth/logout` remains the operation; `DELETE /api/auth/logout` remains absent.
- SSE operations retain `text/event-stream`, event DTOs, meaningful headers, pre-stream JSON errors, heartbeat/malformed-event isolation, open/consume/close/reconnect lifecycle, single-subscription behavior, and post-load offline degradation.
- Invalid, not-found, conflict, upstream-failure, and unavailable outcomes remain distinct. Absent, null, empty, and populated values remain distinct through Rust, OpenAPI, generated TypeScript, the public facade, and application behavior.
- Operator/research operations remain unlinked from trader flows and preserve their zero-vendor/no-recompute/no-mutation rules. No OpenAPI, Swagger, Redoc, Scalar, dependency-status, or advisory-status route is served.
- Contract generation remains a pure offline graph-to-document operation after dependencies are installed; production startup does not read generation tools or generated contract files.

## Contract tooling behavior

`npm run api:contract:generate` remains the canonical atomic generated-artifact writer and `npm run api:contract:check` remains the canonical non-writing comparison/policy/compile command. Neither may write the pre-edit baseline. Their generated bytes, exact clean/drift/recovery copy, supplementary coverage warning, and closed categories remain unchanged. Candidate comparison and normal check each validate the baseline and required compiled-registration receipt before reporting success.

Repository-owned route construction maps empty or unsupported method metadata, duplicate path-method registration, and duplicate operation identity to `incomplete contract coverage` with safe handler, method/path, or operation identifiers. `unsupported schema construct` remains reserved for an actual schema-representation rejection. Unexpected constructor panic, serialization failure, or exporter-process failure remains `generation tooling failure`. `contract drift` remains reserved for completed byte comparison.

The package/advisory evidence remains separate: the candidate passes `cargo deny check advisories licenses sources bans` with no `RUSTSEC-2024-0436` finding, and `utoipa-axum` and `paste` are absent from project manifests and the locked resolved Cargo graph. These facts do not establish broader security, vulnerability, advisory-freshness, or future-safety claims.
