# Pre-install archive — provider-root files Spire did not own (2026-08-14)

Snapshot taken **immediately before** upgrading spire-os **3.3.0 → 3.13.0**. The installer's only
available path was `--force`, whose plan wipes `.claude/`, `.codex/` and `.grok/` and rebuilds them,
preserving exactly one file (`.claude/settings.local.json`). These **106 files** were present in
those roots but **absent from the installation receipt's artifact list**, so the wipe would have
removed them with no record.

They are copied here verbatim (`shutil.copy2`, timestamps preserved) so nothing is decided by
accident. **Triage them, then delete this whole folder** — everything here also exists in git
history before commit `16251fe`, so this archive is a convenience, not the only copy.

## Not archived, deliberately

Three files differed from the receipt but are **Spire's own, with nothing hand-written in them**:

- `.grok/tools/contract_lint.mjs` and `.grok/tools/design_system_ready.mjs` — diffed against their
  `.claude` twins with provider tokens neutralised: the *only* differences are wording for Grok's
  lack of slash commands (*"run design/DESIGN_SYSTEM_METHOD.md"* vs *"run /design-system"*), which
  is the documented P10 capability degradation. Generated variants, safely regenerated.
- `.spire/AGENTS.md` — listed in the receipt but already missing on disk; the install restores it.

## How to restore something

```bash
cp -r archive/pre-spire-3.13-provider-roots/.claude/company .claude/
```

Then delete the folder once you've decided:

```bash
rm -rf archive/pre-spire-3.13-provider-roots
```
